# cairn-save

이 대화를 사용자의 Cairn 블로그에 **세션 노트(raw)**로 남긴다. raw는 근거다. 나중에 다른 AI가 이것을 읽고 wiki를 만든다.
그래서 해석보다 **실제로 일어난 일과 그 근거**가 중요하고, 저장된 뒤에는 고칠 수 없다.

- 노트 규칙: [references/note-rules.md](references/note-rules.md) — 2단계 전에 읽는다
- 검토자 지시문: [references/reviewers.md](references/reviewers.md) — 5단계 전에 읽는다
- 도구별 차이: [references/tools.md](references/tools.md)

사용자가 `/cairn-save` 뒤에 적은 말은 노트의 방향(제목, 강조할 점)으로 참고한다: $ARGUMENTS
그 말에 "빠르게"가 있으면 **빠른 모드**: 5·6단계 대신 경계 검토 한 번만 하고, 7단계는 건너뛴다.

## 체크리스트

아래를 답에 복사해 두고 하나씩 표시하며 진행한다.

```
- [ ] 1. 연결과 모드 확인
- [ ] 2. 근거 묶음
- [ ] 3. 초안과 근거표
- [ ] 4. 기계 검사
- [ ] 5. 사실 검토 → 고치기
- [ ] 6. 경계 검토 → 고치기
- [ ] 7. 다시 검토 (최대 2번)
- [ ] 8. 미리보기와 확인
- [ ] 9. 저장과 결과
```

## 1. 연결과 모드 확인

- cairn MCP 서버의 `check_session`과 `save_session` 도구가 보이지 않으면 멈추고 알린다:
  "Cairn 블로그에 연결되지 않았어요. 터미널에서 `cairn connect <블로그 주소>`로 연결하거나, AI 도구의 MCP·커넥터 설정에서 cairn에 로그인해 주세요."
- 셸 명령을 실행할 수 있고 `{{SKILL_DIR}}/scripts/`가 있으면 **로컬 모드**, 아니면 **앱 모드**다.
- 로컬 모드면 실행한다:

  ```bash
  node {{SKILL_DIR}}/scripts/context.mjs
  ```

  결과의 `work`(작업 폴더), `session_id`(대화 id, 없을 수 있음), `tool`, `project`, `site`를 기억한다.

## 2. 근거 묶음

note-rules.md 3장의 근거 묶음을 만든다.

- 로컬 모드: `node {{SKILL_DIR}}/scripts/evidence.mjs <work>`. 결과가 `transcript: null`이면 대화 원문을 읽지 못한 것이다. git 부분만 만들어지므로, 사용자 메시지(글자 그대로)와 명령 결과를 대화에서 `<work>/evidence.md` 아래에 옮겨 적는다.
- 앱 모드: 대화에서 직접 옮겨 적는다. 사용자 메시지는 글자 그대로, 번호는 U1부터.
- 대화 원문을 쓰지 못했으면 8단계 미리보기에 "원문 대조 없음"을 적는다.

## 3. 초안과 근거표

note-rules.md의 원칙대로, 4장의 모양으로 쓴다 (로컬 모드는 `<work>/draft.md`).
먼저 대화 전체를 훑어 빠짐없이 쓰고, 그다음 덜어낸다.

## 4. 기계 검사

1. `check_session`을 부른다. 노트의 칸(제목, 태그, 한 일, 결정, 막힌 점, 인용, 기타)만 보내고 근거표와 근거 번호는 뺀다.
   `source_session_id`는 1단계의 `session_id`가 있으면 그것을, 없으면 비운다. `tool`은 tools.md의 값.
   결과의 `request_id`, `source_session_id`, `site`, `existing`, `warnings`를 기억한다.
   `warnings`가 있으면 초안에서 그 값을 `[지움: 종류]`로 바꾼다.
2. 로컬 모드면 `node {{SKILL_DIR}}/scripts/check.mjs <work>`도 실행한다. 인용이 원문과 글자 그대로인지, 근거 번호가 있는지, 한도, 비밀값 무늬를 본다.
3. 문제가 있으면 고치고 다시 검사한다.

## 5~7. 검토

reviewers.md의 지시문을 그대로 쓴다. 검토자는 **이 대화를 모르는 다른 맥락**이어야 한다. 띄우는 방법은 tools.md의 순서(하위 에이전트 → 다른 AI 명령줄 → 직접)를 따른다.
검토자에게는 지시문의 해당 부분과 파일 경로(또는 내용)만 넘기고, 작성자의 생각이나 판단은 넘기지 않는다.

5. **사실 검토:** 초안 + 근거 묶음 + 노트 규칙. 치명·중요 지적은 고치거나, 근거 번호를 대고 반박한다.
6. **경계 검토:** 고친 초안 + 노트 규칙. 치명·중요 지적을 고친다.
7. **다시 검토:** 지적 목록 + 고친 초안. 지적마다 고침 / 안 고침. **최대 2번.** 그래도 남은 것은 "확인 필요"로 8단계에 올린다.

## 8. 미리보기와 확인

근거표와 근거 번호를 뺀 노트를 보여주고 묻는다.

```
올릴 곳: <site> (비공개로 저장돼요)
검토: 사실 · 경계 · 다시 검토 n번 · 고친 곳 n · 확인 필요 n  (독립 검토가 아니었거나 원문 대조가 없었으면 그렇다고 적는다)
  ⚠ 확인 필요: …
같은 대화의 n번째 저장이에요   (existing이 있을 때)

제목: …
태그: …

## 한 일
…
(내용이 있는 칸만)

올릴까요? 고칠 곳이 있으면 말해 주세요.
```

- 고칠 곳을 말하면 고치고, 4단계 기계 검사만 다시 한 뒤 다시 보여준다.
- 그만두라고 하면 저장하지 않는다.

## 9. 저장과 결과

`save_session`을 부른다: `request_id`, `source_session_id`(4단계의 값), `tool`, `project`, 노트의 칸 (근거표와 근거 번호는 뺀다).
응답을 받지 못했으면(시간 초과, 연결 끊김) **같은 `request_id`로** 한 번 더 보낸다.

| 응답 | 사용자에게 |
|---|---|
| `status: saved` | "저장했어요 · {revision}판" 과 `url` |
| `status: unchanged` | "바뀐 내용이 없어 새 판을 만들지 않았어요" 와 `url` |
| `status: duplicate` | 앞에서 이미 저장된 것. saved와 같게 알린다 |
| `warnings`가 있음 | "서버가 지운 것: …"을 덧붙인다 |
| `code: invalid_request` | `fields`의 칸을 고쳐 같은 `request_id`로 다시 보낸다 |
| `code: forbidden` (`scope: upload`) | "올리기 권한이 꺼진 기기예요. 블로그 관리 화면 → 기기에서 켜 주세요" |
| 로그인이 필요하다는 오류 | "AI 도구의 MCP·커넥터 설정에서 cairn에 다시 로그인해 주세요" |
| 그 밖의 오류 | 오류 문구를 그대로 보여주고, 노트는 대화에 남아 있어 다시 시도할 수 있다고 알린다 |

- 로컬 모드면 끝에 `node {{SKILL_DIR}}/scripts/context.mjs --clean <work>`로 작업 폴더를 지운다 (근거 묶음에는 대화 원문이 있다).
- 공개 여부는 묻지도 정하지도 않는다. 블로그 관리 화면에서 바꾼다.
- 저장이 끝나면 다른 일을 이어서 하지 않는다.
