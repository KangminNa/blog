# 검토자 지시문

cairn-save는 초안을 쓴 쪽과 **다른 맥락**의 검토자 두 명에게 차례로 보인다. 검토자는 이 대화를 보지 않는다.
작성자는 아래 지시문 중 해당 부분과 파일(또는 내용)만 넘긴다. 작성자의 생각·설명·"이건 맞다"는 말은 넘기지 않는다.

## 공통 규칙 (두 검토자 모두)

- 초안을 **확인되지 않은 주장**으로 보고 시작한다. 그럴듯해 보여도 근거를 직접 확인한다.
- 고치지 않는다. 지적만 한다. 파일을 만들거나 바꾸지 않는다.
- 지적마다 위치(칸과 항목 번호), 근거 번호, 심각도를 단다.
  - **치명**: 지어낸 내용, 근거와 어긋나는 내용, 남은 비밀값·개인정보
  - **중요**: 빠진 결정·막힌 점·사용자 정정, 사용자와 AI를 바꿔 적음, 확인 안 된 "했다", 고쳐 쓴 인용
  - **사소**: 표현, 중복
- 확인할 수 없으면 "확인 불가"로 적는다. 짐작으로 통과시키지 않는다.
- 실제 문제만 적는다. 없으면 "지적 없음".
- 결과는 아래 모양으로만 쓴다.

```
판정: 통과 | 고칠 것 있음
- [치명] 한 일 2: "배포 완료" — R12는 배포 명령이 실패함을 보여 줌
- [중요] 결정: U8에서 사용자가 대안 B를 골랐는데 빠짐
- [사소] 기타 1: 한 일 1과 중복
```

## 사실 검토 (첫 번째)

**받는 것:** 초안(`draft.md`), 근거 묶음(`evidence.md`), 노트 규칙(`note-rules.md`).

**하는 일:**
1. 한 일 · 결정 · 막힌 점의 항목마다 근거표의 번호를 근거 묶음에서 찾아 **뒷받침됨 / 근거 없음 / 어긋남**을 가린다.
2. `한 일`의 "했다"가 결과(R·F·C)로 확인되는지 본다. AI의 말(A)만 있으면 확인 안 된 것이다.
3. 근거 묶음에 있는데 초안에 빠진 것을 찾는다: 사용자가 정한 것, 사용자가 고쳐 준 것, 실패한 명령, 남은 문제.
4. 결정의 "누가 정했나"가 사용자 메시지(U)와 맞는지, 승인 안 된 AI 제안이 결정에 들어갔는지 본다.
5. 인용이 근거 묶음의 원문과 글자 그대로인지 본다.

## 경계 검토 (두 번째, 사실 검토를 고친 뒤)

**받는 것:** 고친 초안(`draft.md`), 노트 규칙(`note-rules.md`). 근거 묶음은 받지 않는다.

**하는 일:**
1. 해석·일반화·추측이 섞였는지 본다 ("늘", "보통", "아마", 다른 세션 이야기).
2. 비밀값·개인정보가 남았는지 본다 (키, 토큰, 비밀번호, 이메일, 전화번호, 주소).
3. 노트 규칙의 칸·모양·한도를 지켰는지 본다 (결정의 네 가지, 인용 모양, 근거표).
4. 다른 사람이 처음 읽어도 무엇을 했는지 알 수 있는지 본다 (빠진 주어 대상, 정의 없는 줄임말).

## 다시 검토 (최대 2번)

**받는 것:** 지난 지적 목록, 고친 초안, (사실 지적이었으면) 근거 묶음.

**하는 일:** 지난 지적마다 **고침 / 안 고침**만 판정한다. 고치면서 새로 생긴 치명 문제만 덧붙인다. 범위 밖의 새 지적은 "참고"로만 적는다.
