# 세션 노트 규칙

세션 노트는 Cairn의 **raw**다. 이 대화에서 실제로 일어난 일의 근거이고, 나중에 다른 AI가 이것을 읽고 wiki(해석·정리)를 만든다.
그래서 노트는 해석보다 **일어난 일과 그 근거**를 담는다. raw는 저장된 뒤 고칠 수 없다.

## 목차
1. 원칙 8가지
2. 칸마다 쓰는 것
3. 근거 묶음과 근거 번호
4. 초안 파일 모양
5. 좋은 예 · 나쁜 예

## 1. 원칙 8가지

1. **이 대화에서 일어난 일만.** 다른 대화·다른 세션과 엮거나 일반화하지 않는다 ("이 프로젝트는 늘 …" ✗). 그건 wiki를 만드는 AI의 일이다.
2. **항목마다 근거.** 한 일·결정·막힌 점의 항목마다 근거 번호를 근거표에 단다. 근거가 없는 주장은 쓰지 않거나 "확인 못 한 것"으로 옮긴다.
3. **"했다"는 확인된 것만.** 테스트 통과, 명령 성공, 화면 확인처럼 결과를 직접 본 것만 `한 일`에 쓴다. 만들었지만 결과를 못 봤으면 `막힌 점`에 "확인 못 함"으로 쓴다.
4. **결정은 네 가지.** 무엇을 · 왜 · 고르지 않은 대안 · 누가 정했나 (사용자 / AI 제안을 사용자가 승인). 사용자가 승인하지 않은 AI 제안은 결정이 아니라 `기타`의 "제안"이다.
5. **인용은 글자 그대로.** 말한 사람(사용자 · AI · 도구)을 붙이고, 줄인 곳은 `…`로 표시한다. 고쳐 쓰거나 요약한 것은 인용이 아니다.
6. **이름은 그대로.** 파일 경로, 명령, 함수·테이블 이름, 오류 문구는 대화에 나온 그대로 쓴다. 기억이 흐리면 지어내지 말고 뺀다. 코드는 붙이지 않고 경로·커밋으로 가리킨다 (꼭 필요한 몇 줄만 예외).
7. **비밀값과 개인정보는 지운다.** API 키, 토큰, 비밀번호, `.env` 값, 개인 키, 다른 사람의 이메일·전화번호·주소는 `[지움: 종류]`로 바꾼다. 코드 속 이름(`password: string`, `API_KEY`)은 그대로 둔다.
8. **먼저 빠짐없이, 그다음 덜어내기.** 처음에는 대화 전체를 훑어 빠진 것이 없게 쓰고, 그다음 중복과 군더더기를 덜어낸다. 이 대화를 전에 저장했어도 **대화 전체**를 다시 정리한다 (저장할 때마다 노트 전체가 새 판이 된다).

## 2. 칸마다 쓰는 것

| 칸 | 쓰는 것 | 한도 |
|---|---|---|
| 제목 | 한 일을 한 줄로. 무엇을 했는지가 드러나게 | 200자 |
| 한 일 (`did`) | 확인된 결과와 함께. "무엇을 → 결과(근거)" | 20,000자 |
| 결정 (`decisions`) | 무엇을 · 왜 · 대안 · 누가 | 20,000자 |
| 막힌 점 (`blocked`) | 막혔던 것과 푼 방법, 남은 문제, 확인 못 한 것 | 20,000자 |
| 인용 (`quotes`) | 다시 볼 가치가 있는 원문: 오류 메시지, 핵심 명령, 사용자의 중요한 말 | 4,000자 |
| 기타 (`extra`) | 위에 맞지 않는 것, 사용자가 승인하지 않은 AI 제안 | 20,000자 |
| 태그 | 주제 낱말 3~8개 | 한 개 40자 |

- `한 일`은 꼭 쓴다. 쓸 것이 없는 칸은 비운다.
- 대화에서 쓴 언어로 쓴다. 마크다운 목록·코드 블록을 써도 된다.

## 3. 근거 묶음과 근거 번호

근거 묶음은 노트의 주장을 확인할 원자료다. 이 컴퓨터에서 도는 도구는 `scripts/evidence.mjs`가 대화 원문과 git에서 만들고, 앱에서는 작성자가 대화에서 직접 옮겨 적는다.

| 번호 | 무엇 | 사실의 근거가 되나 |
|---|---|---|
| `U1, U2…` | 사용자 메시지 원문 | 예 (사용자가 말한 것) |
| `R1, R2…` | 실행한 명령과 결과 (앞부분) | 예 (도구가 보여 준 것) |
| `F1, F2…` | 바뀐 파일 | 예 |
| `C1, C2…` | 커밋 | 예 |
| `A1, A2…` | AI가 한 말 | **아니요.** AI의 말은 주장이지 결과가 아니다. 인용할 때만 쓴다 |

## 4. 초안 파일 모양

이 컴퓨터에서 도는 도구는 작업 폴더의 `draft.md`에, 앱에서는 대화 안에 이 모양으로 쓴다. `scripts/check.mjs`와 검토자가 이 모양을 읽는다.

```markdown
# 제목: 세션 저장 API와 동시 저장 테스트
태그: postgres, mcp, 동시성

## 한 일
- save_session 도구를 만들었다. `pnpm test` → 109개 통과
- …

## 결정
- 같은 대화의 저장은 advisory lock으로 하나씩 처리한다. 이유: 세션 행이 없어도 잠글 수 있다. 대안: 행 잠금(첫 저장 때 잠글 행이 없음). 사용자가 승인.

## 막힌 점
- …

## 인용
- 사용자 [U4]: "50번 동시에 저장해도 하나도 잃으면 안 돼"
- 도구 [R9]: "ℹ pass 109"

## 기타
- 제안 (승인 안 됨): …

## 근거표
| 항목 | 근거 |
|---|---|
| 한 일 1 | R9, F2, F3 |
| 결정 1 | U5, U6 |
```

- 인용은 `- 사용자 [U4]: "…"` / `- 도구 [R9]: "…"` / `- AI [A3]: "…"` 한 줄에 하나.
- 근거표는 한 일 · 결정 · 막힌 점의 항목을 위에서부터 번호로 가리킨다.
- **올릴 때**는 `## 근거표`를 빼고, 인용의 `[U4]` 같은 번호도 지운다. 근거 묶음은 이 컴퓨터를 떠나지 않는다.

## 5. 좋은 예 · 나쁜 예

| 나쁜 예 | 왜 | 좋은 예 |
|---|---|---|
| "인증을 깔끔하게 정리했다" | 무엇을 했는지 없음, 근거 없음 | "로그인 쿠키 쓰기 요청에 Origin 확인을 넣었다. `pnpm test` → 119개 통과 [R14]" |
| "배포 설정도 끝났다" | 결과를 보지 않음 | 막힌 점: "배포 설정 파일을 고쳤지만 실제 배포는 확인 못 함 [F7]" |
| 결정: "Redis를 쓰기로 했다" (AI가 제안, 사용자는 답 없음) | 사용자가 정하지 않음 | 기타: "제안 (승인 안 됨): 세션 잠금에 Redis" |
| 인용: 사용자 "테스트는 다 통과시켜 줘" (실제는 "테스트 다 돌려 봐") | 고쳐 씀 | 인용: 사용자 [U2]: "테스트 다 돌려 봐" |
| "이 프로젝트는 항상 Postgres만 쓴다" | 다른 세션과 일반화 | (쓰지 않는다. wiki의 일) |
