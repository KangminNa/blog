# Cairn MVP 기획서

> 작성 2026-10-03 · 상태: 초안
> 전체 결정 기록과 배경은 [기획서.md](기획서.md)에 있다. 이 문서는 첫 버전(v0.1)을 만들기 위한 범위와 설계만 담는다.

---

## 1. 한 줄 정의

**AI 작업 세션을 여러 컴퓨터에서 모아 그래프로 정리하고, 그 자료로 블로그 글을 쓰는 self-hosted 오픈소스 블로그 엔진.**

## 2. MVP의 목표와 대상

**대상**: Docker로 서버를 직접 띄울 줄 아는 개발자. Claude Code 또는 Codex CLI를 일상적으로 쓰는 사람.

**MVP가 증명할 것**
1. 여러 컴퓨터의 AI 세션이 스킬 한 번으로 **빠짐없이** 한 서버에 모인다.
2. 모인 세션이 그래프로 정리되고, **사람이 고친 것이 AI에 덮이지 않는다.**
3. 다른 컴퓨터의 AI 도구가 MCP로 **과거 세션을 찾아 작업에 쓴다.**
4. 그 자료로 **읽기 편한 블로그 글**을 쓰고 발행한다.

**성공 기준**
| 항목 | 기준 |
|---|---|
| 설치 | `docker compose up`부터 첫 세션 도착까지 15분 이내 |
| 올리기 | `cairn-save` 실행부터 그래프에 점이 생길 때까지 3초 이내 |
| 데이터 보존 | 기기 3대가 같은 세션을 동시에 올리는 테스트에서 유실 0건 |
| 사람 우선 | 사람이 고친 칸·연결이 정리 스킬에 의해 바뀌는 경우 0건 |

---

## 3. 핵심 원칙 (바꾸지 않는 것)

1. **원본은 서버 DB(Postgres).** md는 내보내기 형식이다.
2. **세션 vault와 블로그는 서로 의존하지 않는다.** 외래키도 생명주기 공유도 없다. 글이 어느 wiki에서 나왔는지는 그래프에서 모두에게 보이지만, 비공개 wiki·세션의 이름과 내용은 드러나지 않는다 (2026-10-08 변경).
3. **들어온 정보는 버리지 않는다.** 세션은 판(revision)을 추가만 한다.
4. **사람이 정한 것이 우선이다.** AI는 사람이 손댄 것을 제안으로만 바꾼다.
5. **관리 AI는 내 컴퓨터의 AI 도구다.** 서버에는 AI가 없다.
6. **지우기는 관리 모드에서만.** MCP는 올리기·읽기·정리만 한다.

## 4. 구성

```
[내 컴퓨터들]                                  [블로그 서버 · Docker Compose]
 Claude Code / Codex                          ┌───────────────────────────────┐
  ├ cairn-save   (넣기)  ── MCP ─────────────▶│ api    : MCP · REST · 인증 · SSE │
  ├ cairn-tidy   (정리)  ── MCP ─────────────▶│ web    : 블로그 · 그래프 · 관리   │
  ├ cairn-recall (읽기)  ── MCP ─────────────▶│ worker : 후속 작업 · 알림 · 내보내기│
  └ cairn-write  (글쓰기) ── MCP ────────────▶│ db     : Postgres               │
 브라우저 (방문자 / 관리자) ── HTTPS (사용자의 리버스 프록시) ─▶│ files  : 디스크 볼륨     │
 휴대폰 (푸시 알림) ◀───── Web Push ───────────┤                                 │
 메일함 ◀───── SMTP ──────────────────────────┘                               │
                                              └───────────────────────────────┘
```

## 5. MVP 기능 범위

### 5.1 넣는다

| 영역 | 기능 |
|---|---|
| **설치** | Docker Compose 한 벌, 첫 실행 설치 마법사 5단계 (설치 코드 → 주인 계정(아이디·비밀번호) → 블로그 정보 → 플러그인 고르기·설정 → 첫 기기 연결) |
| **인증** | 관리 모드는 주인 아이디·비밀번호 (GitHub 등 외부 로그인은 로그인 플러그인). MCP는 OAuth(로그인한 주인이 승인)와 기기별 토큰(예비). 기기별 권한: 올리기 / 읽기(공개만·전부) / 정리 / 글쓰기. 새 기기는 올리기 + 공개 읽기로 시작하고 나머지는 관리 화면에서 켠다. 연결은 추가 승인 없이 즉시 알림 |
| **스킬** | `cairn-save`(넣기), `cairn-tidy`(정리), `cairn-recall`(읽기), `cairn-write`(글쓰기). 배포는 폴더 복사와 `npx cairn connect <주소>` (배포 전에는 저장소에서 `pnpm cairn connect`). 지원 도구: Claude Code · Codex(`cairn connect`가 스킬·검토자를 넣음), Claude 앱 · ChatGPT(관리 화면 기기 시트의 안내, "앱 연결 허용" 스위치, 스킬 zip). 세션은 스킬을 부를 때만 올린다 (자동 올리기 없음). `cairn-save`는 raw 노트 규칙 + 다른 맥락의 사실·경계 검토 (기획서 2026-10-19) |
| **세션 수집** | 세션 노트(제목 · 한 일 · 결정 · 막힌 점 · 인용 + 기타, 인용 4,000자 넘으면 거절), 판 쌓기, 요청 ID 중복 방지, 1·2차 민감정보 제거, 이미지 첨부(png·jpg·webp·gif, 10MB 이하) |
| **정리** | 일거리 상자(임대·연장·반납), 새 세션 정리, 점검, 충돌 합친 문장 추천. 결과 제출 시 재검사 |
| **그래프** | 방문자: 전체 모양 + 공개 노드만 내용. 관리자: 연결선 만들기·지우기, 주제 만들기·이름 바꾸기·합치기, 세션을 다른 주제로 옮기기, 점 위치 고정, 되돌리기 |
| **그래프 전송** | 내용 없이 점·선의 뼈대만 압축해서 보냄(내용은 누를 때 따로). 배치 좌표는 일꾼이 서버에서 미리 계산. 변경이 생기면 일꾼이 **스냅샷 파일**을 다시 만들고(몰아서 최대 10초에 한 번) 버전을 올림. 방문자용 공개 스냅샷은 모두에게 같아서 한 번 만들어 그대로 캐시(ETag, 리버스 프록시 캐시 가능). 관리 모드는 처음에 스냅샷 + 이후 SSE로 바뀐 점·선만. 브라우저는 마지막 스냅샷을 IndexedDB에 두고 먼저 그린 뒤 확인 |
| **충돌과 동시성** | 칸 단위 3-way 합치기, 편집 임대, 사람 표시, 변경 기록 |
| **변경 묶음과 검토 규칙** | git처럼 모든 그래프 변경을 변경 묶음(커밋)으로 남긴다. AI의 묶음은 서버가 검토 규칙으로 바로 합치기 / 검토(승인함) / 거부를 정한다. 주인은 관리 화면에서 규칙마다 값을 고른다. 되돌리기는 묶음 하나, 또는 기기 + 기간 단위 |
| **대정리** | AI로 전체를 한 번에 정리할 때는 바로 적용하지 않고 **정리 계획**을 만든다. 전후 비교를 보고 전부·카테고리별·작업 종류별로 골라 승인하면 일꾼이 나눠 적용하고, 한 번에 되돌릴 수 있다. 비공개 → 공개 전환은 한 번 더 확인. 그동안 새 세션은 도착 구역에 평소처럼 쌓임. wiki를 합치면 옛 id → 새 id 연결표를 남겨 글의 참고가 깨지지 않음 |
| **블로그 (방문자)** | 글 목록(카드 그리드, 정렬 탭), 글 페이지(가운데 정렬 본문, 사진·갤러리·영상·링크 카드·큰 인용·구분선, 목차, 시리즈, 이전/다음 글), 카테고리, 검색, RSS |
| **블로그 (관리)** | 글쓰기·수정·휴지통·발행, 쓰는 화면이 곧 보이는 편집기(Tiptap, 저장은 md) + 도구 막대, 사진 업로드, 카테고리 관리(2단계), vault 재료 패널(검색해서 복사), 블로그 문체 가이드, **참고 wiki**(글의 대표 wiki와 참고 wiki. 세션 출처는 wiki를 거쳐 봄) |
| **글감 상자** | 세션·사진·파일·참고 링크·참고할 내 글·메모를 담는 작업대. 관리 모드(그래프에서 끌어 담기, 업로드, 링크 붙여 넣기)와 AI 도구(`basket_add`) 양쪽에서 담음. 글과 연결을 저장하지 않음. "AI에게 초안 맡기기"는 일거리로 등록 |
| **알림** | 관리 모드 알림 센터(실시간), AI 도구 안 알림(MCP 응답에 첨부), **브라우저 푸시**, **이메일**(즉시 보안 알림 + 하루 요약) |
| **내보내기** | 관리 화면에서 전체를 보관 형식(md·yml·사진) zip으로 내보내기, DB 백업 명령. 자동 백업은 GitHub 동기화 플러그인 |
| **검색** | **1차는 브라우저에서**: 이미 받은 그래프 안(제목·주제·프로젝트·태그·날짜·짧은 요약)은 서버 없이 즉시 찾고 거른다. 그래프를 그린 뒤 작은 검색 색인 파일을 따로 받아 둔다. **2차만 서버로**: 본문 내용, 의미 검색, 아직 받지 않은 영역(나중의 부분 로딩), 1차 결과가 없거나 "본문까지 찾기"를 눌렀을 때. 서버 검색은  키워드(pg_bigm, 에러 메시지·코드 이름처럼 정확한 말) + 의미(pgvector, 표현이 달라도 비슷한 내용) → 두 결과를 합쳐 순위(RRF) + 최근성·그래프 거리 가중치. 서버에 내장한 소형 다국어 임베딩 모델(CPU)로 계산, Ollama·API로 교체 가능. 세션은 칸 단위로 쪼개 색인. **그래프 검색은 방문자 화면과 관리 모드 양쪽에 둔다**: 방문자는 공개 세션·주제만(비공개는 결과에도 개수에도 나오지 않음, 서버에서 거른 뒤 순위 계산), 관리 모드는 전부 + 공개 여부·기기 필터. 하단 메뉴의 검색 버튼과 ⌘K → 결과를 고르면 그 점으로 날아가 이웃을 강조, 멀리서는 주제 덩어리만 보이고 가까이 갈수록 세션이 보이는 단계별 표시 |

### 5.2 넣지 않는다 (다음 단계)

| 미루는 것 | 이유 |

## 6. 사용자 흐름

**처음 설치**: 서버에서 `docker compose up` → 로그의 설치 코드와 주소 확인 → 브라우저로 접속해 설치 코드 입력 → 주인 계정(아이디·비밀번호) 만들기 → 블로그 정보 → 플러그인 → 첫 기기 연결 안내.

**기기 연결**: 노트북에서 `npx cairn connect https://내블로그 [--tool codex]` → 스킬·검토자 복사(M1은 `cairn-save` 하나), MCP 등록 → 브라우저가 열려 로그인 → 기기 이름·권한 선택 → 연결 테스트 통과. Claude 앱 · ChatGPT는 관리 화면 기기 시트에서 "앱 연결 허용"을 켜고, 앱의 커넥터 설정에 `https://내블로그/mcp`를 넣은 뒤 승인, 스킬 zip을 앱에 올린다 (블로그가 공개 https여야 함).

**넣기**: 작업 후 "이 세션 저장해" → 스킬이 노트 작성 → 미리보기 → 확인 → 서버 저장(3초 이내 응답) → "이어서 정리할까요?"

**정리**: "cairn 정리해" 또는 예약 실행 → 일거리 빌리기 → 처리 → 제출 → 결과 보고("세션 5개 정리, 제안 2건").

**다시 쓰기**: 다른 컴퓨터에서 막혔을 때 "지난번에 이거 어떻게 풀었지?" → `cairn-recall`이 검색해 요약.

**관리**: 관리 모드 → 승인함(제안·충돌) → 세션 고치기·공개 설정 → 그래프 편집.

**글쓰기**: 그래프에서 세션을 글감 상자에 담고 사진·참고 링크·참고할 내 글을 더함 → AI 도구에서 "글감으로 초안 써줘" → `cairn-write`가 개요를 보여주고 확인받은 뒤 초안 저장 → 관리 모드 편집기에서 다듬어 발행. AI 없이 직접 쓸 때는 재료 패널에서 세션을 검색해 복사.

## 7.5 그래프 형태 (2026-10-08 확정)

그래프는 **나무 + 선**이다. 모든 점은 주소가 딱 하나라서 그 자리에 놓이고(나무), 주소 말고 다른 연결은 선으로 따로 보인다(그물).

**점 네 종류**

| 점 | 누가 만드나 | 주소 |
|---|---|---|
| 카테고리 | 사용자가 만든다. AI는 새 카테고리를 제안만 한다 | 지도 위의 구역 |
| wiki | AI가 여러 세션을 모아 쓴 정리 문서 (사람도 직접 쓰고 고친다) | 카테고리 하나 |
| 세션 | AI 도구가 올린 원본 | 대표 wiki 하나. 아직 정리 전이면 **도착 구역** |
| 블로그 글 | 사람이 발행 | 대표 wiki 하나의 꼭대기. 참고한 wiki가 없는 글은 그래프에 나오지 않는다 |

**선 (주소 말고 다른 연결)**

| 선 | 뜻 |
|---|---|
| 재료 | 세션 → 대표가 아닌 다른 wiki. 세션 하나가 여러 wiki의 재료가 될 수 있다 |
| 참고 | 글 → 대표가 아닌 다른 wiki |
| 링크 | wiki ↔ wiki (`[[ ]]`) |

모든 연결은 흐린 선으로 보이고, 점을 고르거나 올리면 그 점과 이웃만 밝아진다 (옵시디언 그래프 뷰와 같은 방식). 주소 선은 조금 진하게, 주소 밖 선은 종류별 모양(점선 등)으로 구분한다.

**공개 범위**: 카테고리 이름은 공개. wiki와 세션은 각자 공개·비공개가 있다. 글은 임시(나만) · 공개(목록에 보임) · 링크만(주소로만, 목록·검색·RSS 제외) 중 하나다 (2026-10-24). 글과 wiki 사이의 연결은 방문자에게도 보이지만, 비공개 wiki·세션은 자리만 보이고 이름·내용·날짜는 보이지 않는다.

**사용자가 바꾸는 것**: 구역 기준(카테고리·프로젝트·AI 도구·기간), 보이는 단계(세션·wiki·글), 선 보기(고른 것만·항상·끄기). 카테고리가 아닌 기준으로 나누면 wiki는 재료 세션이 가장 많은 구역에 놓인다.

**모양**: 옵시디언 그래프 뷰처럼 점과 선이 힘으로 자리를 잡는 평면 그래프 (2026-10-08 확정). 점 종류는 색·크기·모양으로 구분하고, 같은 카테고리는 같은 색 무리로 모인다. 캐릭터나 게임 요소는 두지 않는다. 위에서 내려다본 지도·레이어·3D 시안은 검토 후 쓰지 않기로 했다.

**데이터에 생기는 일 (구현 전에 인터페이스로 제안)**
- 저장 방식은 [테이블 설계](테이블설계.md) 3장 "그래프 = 대표 하나 + 선" (2026-10-10 반영). 대표는 열(`wiki_id`, `category_id`, `main_wiki_id`), 비어 있으면 도착 구역·미분류, 재료·링크·비슷함만 선.
- 글 → wiki 연결은 blog가 갖고, 모듈 사이 외래키는 두지 않는다. vault의 그래프는 blog의 이벤트(`blog.post.published` 등)를 받아 사본(`vault.post_marks`)에 글 자리를 적어 둔다. vault는 여전히 blog를 import하지 않는다.
- 정리 스킬(`cairn-tidy`)의 일이 "주제 붙이기"에서 "wiki 쓰기·고치기, 대표 wiki와 재료 정하기, 카테고리 제안"으로 커진다.

## 10. 개발 스택

> 2026-10-10에 실제 결정대로 고쳤다. 라이브러리는 필요해지는 단계에서 [객체 설계](객체설계.md) 10장 순서(겪은 문제 → 자리 → 비용 → 고치는 범위 → 빼는 방법)로 정하고 넣는다.

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | **TypeScript** (전 구간) | 스킬 설치 도구(npx), MCP 공식 SDK, 웹이 모두 같은 언어. 기여자가 한 언어만 알면 됨 |
| 런타임 | **Node.js 24** | 내장 테스트(`node:test`), `fetch`, `zlib.crc32` 등 내장 기능으로 의존성을 줄임 |
| 저장소 구조 | **pnpm 워크스페이스** 모노레포 (Turborepo 없음) | 앱이 둘이라 빌드 도구가 따로 필요 없음 |
| API 서버 | **NestJS** (Express) | 모듈·의존성 주입·가드로 구조가 강제되어 모듈 규칙과 잘 맞음. 입력 검사는 라이브러리 없이 Request 클래스(`BaseRequest`) |
| MCP | **MCP TypeScript SDK** (Streamable HTTP, OAuth 도우미) | 규격이 크고 자주 바뀜. `platform/base` 안에서만 감싸 쓰고, 모듈은 `BaseTool`만 앎 (M1) |
| 웹 | **Next.js** (App Router, standalone 출력) | 블로그는 검색 노출을 위해 서버 렌더링, 관리 모드는 클라이언트 화면. 한 앱에서 둘 다 |
| DB | **Postgres 17+** + **pg_bigm**(한국어 키워드) + **pgvector**(의미 검색) | 원본 저장소. 확장 둘을 넣은 Cairn 전용 DB 이미지 |
| 쿼리 | **postgres.js** (ORM 없음) | SQL을 그대로 씀(`SKIP LOCKED`, JSONB, 버전 비교). `platform/base`의 `Database`만 가져옴 |
| 마이그레이션 | **SQL 파일 + dbmate** (`db/migrations`) | 부분 인덱스, 모델별 HNSW 인덱스, 트리거, DEFERRABLE 외래키를 그대로 씀 |
| 후속 작업 | **outbox + 자체 일꾼** (`main.worker.ts`) | Postgres만으로 동작. Redis·작업 큐 라이브러리 없음 |
| 인증 | 주인: **아이디·비밀번호** (Node 내장 scrypt, 라이브러리 없음). 외부 로그인(GitHub 등)은 플러그인. 기기: **MCP OAuth 2.1** (SDK 도우미) | 외부 서비스 없이 설치가 끝남 |
| 보관 형식 | **`yaml`**(앞부분 읽기·쓰기, 의존성 없음), zip은 `node:zlib`으로 직접 | 사람이 GitHub에서 고친 파일도 읽어야 함 (M1 보관 형식) |
| 임베딩 | 서버 내장 소형 다국어 모델(384차원) 후보, M2에서 평가 | 로그인·API 키 없이 의미 검색 |
| 그래프 화면 · 편집기 · md 렌더링 · 알림 | 그 단계(M2·M4·M5)에서 정함 | 후보: Sigma.js, CodeMirror 6, unified/remark, web-push |
| 실시간 | **SSE** (M2) | 단방향이라 WebSocket보다 단순 |
| 파일 | 디스크 볼륨, 내용 해시 이름 | S3 호환은 다음 단계 |
| 배포 | **Docker Compose** (db · migrate · server · worker · web). HTTPS와 리버스 프록시는 사용자가 준비 | 프록시 설정(경로 `/api`·`/mcp`·`/oauth`·`/.well-known` → 서버, 나머지 → 웹, SSE 버퍼링 끄기, 업로드 크기)을 문서로 제공 |
| 스킬 | SKILL.md 표준 | Claude Code부터. Codex·Gemini는 다음 |
| 테스트 | **`node:test`** + API 테스트 도구(`ApiClient`, 테스트 전용 DB) | 의존성 없이 실제 DB로. 화면 테스트 도구는 웹을 만들 때 정함 |

**저장소 구조** (폴더는 필요해지는 단계에서 하나씩 만든다)
```
cairn/
├── apps/
│   ├── server/     NestJS. 진입점: main.api.ts (REST·MCP·인증), main.worker.ts (일꾼), main.cli.ts (명령줄)
│   │               src/modules/ platform · account · vault · blog · mcp (지도는 modules.json)
│   └── web/        Next.js (블로그, 그래프, 관리 모드, 설치 마법사)
├── packages/
│   └── cli/        npx cairn connect (M1)
├── skills/         cairn-save (M1) · cairn-tidy · cairn-recall · cairn-write
├── plugins/        플러그인 (comments-giscus, sync-github)
├── db/             DB 이미지(Postgres + pg_bigm + pgvector), SQL 마이그레이션
├── scripts/        모듈 경계 검사, 플러그인 화면 맞추기, 테스트 실행
├── .claude/        훅, 경로별 규칙
├── AGENTS.md       모든 AI 도구 공통 규칙
├── CLAUDE.md       @AGENTS.md를 가져오고 Claude 전용 메모만 추가
└── docs/
```

**경계 규칙**: 웹은 DB에 접근하지 않고 반드시 서버 API를 거친다 (블로그 서버 렌더링도 내부 API 호출). 도메인 규칙은 각 모듈의 Entity·Policy에 두고, Service는 트랜잭션과 순서만 맡는다 ([객체 설계](객체설계.md)). 저장소는 하나지만 server·worker(같은 서버 앱의 두 진입점)·web은 따로 띄운다.

**AI 작업 규칙 문서 (3단)**

| 단계 | 파일 | 언제 읽히나 | 담는 것 |
|---|---|---|---|
| 저장소 | `AGENTS.md` (+ `CLAUDE.md`가 가져옴) | 시작할 때 항상 | 프로젝트 요약, 핵심 원칙 6개, 모듈 지도, 명령어, 작업 순서, 커밋 규칙, 경계 규칙. 200줄 이하 |
| 모듈 | `apps/*/CLAUDE.md`, `apps/server/src/modules/{account,vault,blog,platform,mcp}/CLAUDE.md`, `packages/*/CLAUDE.md`, `skills/CLAUDE.md` | 그 폴더의 파일을 다룰 때 | 모듈의 역할, 공개 인터페이스, 지켜야 할 불변식, 따라 할 예시 파일, 테스트 방법, 하지 말 것. 80줄 안팎 |
| 관심사 | `.claude/rules/*.md` (`paths:`로 대상 지정) | 해당 경로의 파일을 다룰 때 | 여러 모듈에 걸친 규칙: SQL·트랜잭션, 마이그레이션, React 컴포넌트, 테스트, MCP 도구, 인증·보안 |

강제는 문서가 아니라 도구로 한다: 저장 시 Biome 포맷·린트(훅), 바뀐 패키지 타입 검사(훅), 적용된 마이그레이션 수정 차단(훅), 의존 경계 린트, CI 최종 확인. 모듈 동작을 바꾸는 PR은 그 모듈의 CLAUDE.md도 함께 고친다.

## 12. 위험과 대응

| 위험 | 대응 |
|---|---|
| AI 도구의 세션 파일 형식이 공식 문서화되지 않아 바뀔 수 있음 | 세션 노트는 AI가 대화 맥락으로 직접 쓰고, 파일 읽기는 보조로만. 형식 변경은 어댑터에서 흡수 |
| MCP 클라이언트마다 OAuth 지원 정도가 다름 | 기기별 토큰을 예비로 항상 제공 |
