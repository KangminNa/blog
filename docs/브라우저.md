# Cairn 서버 브라우저

로그인된 브라우저로 하는 일(탭 읽기, 브라우저 에이전트: 사이트 일 · 둘러보기 · 결재된 클릭)을 이 문서 하나에 모은다.
결정의 이유는 [기획서](기획서.md) 결정 기록(2026-11-08 · 2026-11-14), 2차의 목표는 [서브 나](서브나.md) 7장, 기능 패키지의 틀은 [객체설계](객체설계.md) 12장, 배포 순서는 [README](../README.md) 6장.

## 1. 하는 일

| 일 | 흐름 | AI | 남는 것 |
|---|---|---|---|
| 탭 읽기 | 관리자가 주소를 맡긴다 → 러너가 탭으로 열어 제목과 보이는 글자만 읽고 닫는다 | 없음 | `browser_tabs.reads` |
| 사이트 일 | 관리자(또는 대표의 위임)가 사이트에 일을 맡긴다 → 서버 러너의 AI가 로그인된 프로필로 양식을 채우고 마지막 버튼 앞에서 멈춘다 → 러너가 버튼을 붙잡아 결재를 올린다 → 승인되면 러너가 같은 버튼인지 보고 누른다 | 서버 러너의 구독 CLI(Claude · Codex) + Playwright MCP | 작업 · 결재 · `clicks` · `shots` |
| 둘러보기 | 대상 없이 맡긴다 → 일마다 새 빈 창(로그인 없음)으로 공개 사이트를 조사한다. 아무것도 제출하지 않는다 | 같음 | 작업(결과 글) · `shots` |
| 로그인 필요 | 사이트 일이 로그인 화면을 만나면 러너가 "로그인 필요" 결재를 올린다 → 관리자가 콘솔 화면에서 로그인하고 "로그인했어요" → 같은 작업이 이어진다 | 없음 | 결재 · `sites.login_needed_at` · `shots` |

## 2. 원칙

- **AI는 러너에서만 브라우저를 움직인다.** 서버 본체에는 AI가 없다 (원칙 6). 서버는 관리자가 콘솔에서 화면을 보고 누르는 중계와 사이트 세션 지우기로만 브라우저에 붙는다 (3장).
- **마지막 버튼은 결재 뒤에 믿는 코드가 누른다 (원칙 7, 2026-11-14).** AI는 제출 · 결제 · 게시 버튼 앞에서 멈추고 `browser-stop.json`을 남긴다. 결재는 AI가 아니라 러너(AI 없음)가 그 버튼의 지문과 화면을 붙잡아 올린다. 승인되면 붙잡은 러너가 같은 탭 · 같은 주소 · 같은 지문 · 가장 위 요소인지 다시 보고, 같을 때만 실제 마우스 이벤트로 누른다. 다르면 누르지 않고 관리자가 콘솔 화면에서 직접 한다. 많아야 한 번 누른다.
- **브라우저를 쓰는 에이전트는 비공개를 읽지 않는다.** 권한 `browse`는 `read_all` · `write`와 함께 줄 수 없다 (서버 규칙 + DB CHECK). 브라우저 일을 맡기는(`delegate_task`) 쪽도 `read_all` · `write`가 없어야 한다 (`DelegationPolicy`): 지시문이 곧 브라우저 담당의 재료라서 비공개가 지시를 타고 바깥 사이트로 갈 수 있다. 그런 대표는 브라우저 일을 맡기지 못하고 관리자가 브라우저 메뉴에서 맡긴다.
- **둘러보기는 로그인된 프로필을 건드리지 않는다.** 일마다 새 빈 컨텍스트(`--isolated`)라 쿠키가 없고, MCP가 끝나면 사라진다. 이 서버 · 내부망 · 메타데이터 주소는 러너의 프록시(`ExploreProxy`)가 막는다.
- **CDP는 서버 밖으로 열지 않는다. 화면은 관리자 확인 뒤에만 넘긴다.** 조종 중계(9223)는 서버와 브라우저만 붙는 망에 있고, 콘솔 화면 API는 관리자만 부른다. 밖으로 여는 포트 · 비밀번호가 없다 (neko의 실시간 영상은 2026-11-14에 지웠다).
- **브라우저 작업은 서버 러너만 받는다.** 내 컴퓨터 러너는 탭 읽기만 한다 (평소 쓰는 계정에 가까운 브라우저를 AI에게 맡기지 않는다).
- **비밀번호는 저장하지 않는다.** 관리자가 콘솔 화면에서 로그인하고(2단계 인증 포함) 브라우저는 로그인 상태만 기억한다. 브라우저의 비밀번호 저장은 정책으로 꺼져 있다.

## 3. 구성

```
관리자 브라우저 ─https─ 앞단 프록시 ─┬─ 웹 · 콘솔 (운영 › 브라우저: 화면 그림 · 클릭 · 입력, 세션 지우기, 결재 카드)
                                     └─ Cairn 서버 (/api · /mcp)

Cairn 서버 ── 전용 망(browser) ── 조종 중계 9223 ─┐   (콘솔 화면 · 세션 지우기: 관리자만)
서버 러너 ──MCP──▶ Cairn 서버                     │
   │ CDP 127.0.0.1:9222 (브라우저와 같은 네트워크) ▼
   │                    브라우저 컨테이너 (Xorg + openbox + Chromium, 로그인 프로필 볼륨)
   ├─ Playwright MCP (사이트 일): 기본 컨텍스트, 허용 출처만 ──▶ 등록한 사이트
   ├─ Playwright MCP (둘러보기): 새 빈 컨텍스트 ─ ExploreProxy(127.0.0.1) ─▶ 공개 사이트 (내부 주소 막힘)
   └─ ClickRunner: 승인된 클릭을 CDP로 다시 확인하고 누른다
```

- 서버 브라우저는 선택 구성 `docker-compose.browser.yml`이다. 켜면 서버 러너가 브라우저의 네트워크를 함께 쓴다(`network_mode: service:browser`). 러너에게 브라우저는 127.0.0.1이라 Chrome의 Host 검사를 중계 없이 지나고, CDP가 컨테이너 밖으로 나가지 않는다.
- 이미지는 neko 3.2.0(amd64 · arm64, digest 고정)의 화면과 Chromium에 실행 옵션(`browser/chromium.conf`) · 정책(`browser/policies.json`) · 조종 중계(`browser/cdp-relay.py`)를 더한다. **neko 서버(영상 · 원격 입력 · 비밀번호)는 끈다** (supervisord `autostart=false`). 화면 크기는 neko가 아니라 Chromium 창(`--window-size=1280,720`, openbox 최대화 끔)으로 정한다. Chromium 로그는 치명적인 것만(`--log-level=3`), 10MB × 2.
- **콘솔 화면 (2026-11-14):** 서버(`browser-tabs`의 `BrowserScreenGateway`)가 전용 망으로 조종 중계에 붙어 화면을 JPEG로 받고 클릭 · 스크롤 · 글자 · 키 · 이동 · 뒤로를 보낸다. 콘솔은 열려 있고 보이는 동안 1초마다 다시 그리고, 지금 상태를 한 줄로 보인다(보는 중 · 멈춤(창이 가려짐) · 꺼짐: 이유). 꺼져 있으면 10초마다만 묻는다. HTTPS(443) 하나로 끝난다.
  - 전용 망에는 브라우저(와 그 네트워크를 함께 쓰는 서버 러너)와 서버만 붙는다. 웹 · DB · 일꾼은 9223에 닿지 않는다.
  - Chrome은 Host가 이름이면 거절해서(`Host header is specified and is not an IP address or localhost`) 서버는 서비스 이름 `browser`를 IP로 풀어 붙는다.
  - 화면 API는 관리자만 부른다. 입력한 글자(로그인 비밀번호일 수 있다) · 주소 · 화면은 어디에도 남기지 않는다. 주소 이동은 http(s)만.
- 정책(`URLBlocklist`)은 `localhost` · `127.0.0.1` · `[::1]` · `0.0.0.0` · `169.254.169.254` · `metadata.google.internal`과 compose 서비스 이름(`cairn-server` · `server` · `browser` · `db` · `web` · `worker` · `runner`)을 막는다. IP 대역은 정책에 적을 수 없어 둘러보기는 러너의 프록시가 막는다. 프록시를 거치지 않는 WebRTC UDP도 정책으로 막는다(`WebRtcIPHandling`).
- 내 컴퓨터에서는 러너 전용 Chrome 프로필을 `--remote-debugging-port`로 띄우고 `CAIRN_BROWSER_URL`을 주면 탭 읽기를 한다 (`apps/runner/.env.example`).

## 4. 흐름

### 탭 읽기

1. 관리자: `POST /api/p/browser-tabs/reads { url }` → `reads`에 `requested`.
2. 러너의 `TabReader`(일과 따로 돎): `browser_tab_pending`으로 받는다. 없으면 15초, 패키지가 꺼져 있으면 5분 뒤 다시 묻는다.
3. `BrowserTabs`: 새 탭 → 다 뜨면(30초) 1.5초 뒤 제목과 `innerText` → 탭 닫기.
4. `browser_tab_save`로 남긴다. 페이지 문제(열지 못함 · 안 뜸)는 이유를 남기고, 브라우저에 닿지 못하면 남기지 않고 기다렸다 다시 한다. 로그에는 주소의 호스트만.

### 사이트 일과 결재된 클릭

1. 관리자: 사이트를 등록하고(이름 · 시작 주소 · 허용 출처), 콘솔 화면에서 그 사이트에 로그인한다.
2. 관리자: 사이트에서 "맡기기" → 패키지가 `task.task.requested`(종류 `browse`, 대상 `browser_site` · 사이트 id · 판)를 남긴다. 담당을 비우면 `browse` 권한이 있는 에이전트가 맡는다. 대표(공개 읽기만)가 `delegate_task { kind: browse, target_kind: browser_site, … }`로 브라우저 담당에게 맡겨도 같다 (사이트는 `browser_sites`로 고른다).
3. 서버: `browse` 작업은 `next_jobs`에서 `browser: true`를 알린 러너에게만 빌려 준다. 러너는 사이트 일(대상이 있는 browse)이 도는 동안 `browser`를 알리지 않는다 (사이트 일은 러너마다 하나씩).
4. 서버 러너(`BrowseStage`): 브라우저에 닿는지 묻고(3초), 닿지 못하면 돌려주고 기다린다. `browser_job`으로 어디서 돌지 받는다(사이트 값 · 로그인 필요 · 붙잡았던 페이지). 브라우저 자리(`BrowserSlot`, 결재된 클릭과 나눈다)를 잡고 지금 탭을 기억한다. 사이트에 로그인 필요가 적혀 있으면 AI 없이 로그인 결재로 간다 (아래).
5. AI CLI에 cairn MCP와 Playwright MCP(`--cdp-endpoint` · `--allowed-origins` · `--output-dir`)를 붙여 띄운다. 스킬은 `cairn-browse`: 새 탭을 열고, 채우고, 단계마다 JPEG 화면을 찍고, 마지막 버튼 앞에서 작업 폴더에 `browser-stop.json { stop: "final_click", page_url, button: { role, name, nth }, note }`을 쓰고 끝낸다. 결재는 올리지 않는다.
6. 러너: AI가 찍은 단계 화면을 올리고(`browser_shot_save`), AI가 새로 연 탭에서 그 주소를 찾아 접근성 트리에서 역할 + 이름으로 버튼을 다시 찾는다 (`BrowserPages.hold`). 보이고 · 켜져 있고 · 한가운데의 가장 위 요소여야 한다. 지문(주소(# 앞) · 역할 · 이름 · 순번 · 태그 · type · form action · method · 글자의 sha256)과 멈춘 화면을 만들어 `browser_click_hold`로 붙잡고(페이지는 허용 출처 안이어야 한다), 작업 토큰으로 `request_approval { action: browser.site.publish, target_kind: browser_click, target_id: 클릭, target_version }`을 올린다. 작업은 결재를 기다린다.
7. 관리자: 결재 카드에서 페이지 · 버튼 · 멈춘 화면(버튼 자리에 테두리)을 보고 "누르기"(승인). 고칠 게 있으면 수정 요청: 클릭은 닫히고 AI가 붙잡아 두었던 탭에서 고친 뒤 다시 멈춘다.
8. 패키지: `task.approval.granted`를 받아 클릭을 `approved`로 (판이 결재한 판과 같을 때만). 작업은 임대 없이 결과를 기다린다.
9. 러너의 `ClickRunner`(5초마다 `browser_click_next`, 붙잡은 러너만 받는다): 자리를 잡고 같은 탭 · 같은 주소 · 같은 지문 · 가장 위 요소인지 다시 본다. 같으면 실제 마우스 이벤트로 누르고, 새 페이지면 뜰 때까지(최대 10초) 기다려 결과 화면과 주소를 `browser_click_save { outcome: clicked }`로 남긴다 → 패키지가 `plugin.browser_tabs.click_done { approvalId, outcome: done }` → 코어가 작업을 끝낸다. 다르면 누르지 않고 `changed`와 그때의 화면 → 작업 실패("페이지가 바뀌어 누르지 않았어요 … 콘솔 화면에서 직접 눌러 주세요") → 관리자가 직접 누르고 클릭 목록에서 "직접 눌렀어요"로 기록한다.

### 로그인 필요

1. AI가 로그인 화면을 보면 아무것도 치지 않고 `browser-stop.json { stop: "login", page_url }`을 쓰고 끝낸다. 사이트에 이미 로그인 필요가 적혀 있으면 러너가 AI를 띄우지 않는다 (관리자가 로그인할 탭을 열어 둔다).
2. 러너가 그 탭을 찍어 `browser_login_needed`로 사이트에 표시(`login_needed_at`, 판은 올리지 않는다)와 화면을 남기고, `request_approval { action: browser.site.login, target_kind: browser_site, … }`을 올린다. 작업은 기다리고 결재 알림 · 푸시가 간다.
3. 관리자가 콘솔 화면에서 로그인(2단계 인증 포함)하고 결재 카드의 "로그인했어요"를 누른다 (= 정해진 말의 수정 요청). 패키지가 표시를 비우고, 코어가 같은 작업을 대기열로 돌린다(대상 `browser_site`). 위임 사슬(위 작업이 하위 작업을 기다리는 것)은 끊기지 않는다. 반려하면 작업이 취소된다. API로 승인하면 쓰지 않는 길이라 실패로 끝난다.

### 둘러보기

1. 관리자: `POST /api/p/browser-tabs/explore { requestId, instruction, agentId? }`, 또는 대표가 대상 없이 `kind: browse`로 맡긴다.
2. 러너: `browser_job`이 `explore`. 프록시(`ExploreProxy`, 127.0.0.1의 빈 포트)를 띄우고 Playwright MCP를 `--isolated --proxy-server`로 붙인다. 브라우저 자리를 쓰지 않아 여럿이 함께 돈다.
3. AI는 공개 사이트를 열어 조사하고 결과를 답에 쓴다. 단계 화면은 사이트 일과 같이 남는다. `browser-stop.json`을 써도 러너는 누르지 않는다.
4. MCP가 끝나면 그 컨텍스트도 사라진다 (CDP 연결이 끊기면 Chrome이 지운다, 시험으로 확인).

### 사이트 세션 지우기

`POST /api/p/browser-tabs/sites/:id/clear-session` (관리자): 서버가 조종 중계로 로그인된 프로필에 빈 탭을 열어, 그 사이트 출처의 호스트로 가는 쿠키만 지우고(`Network.deleteCookies`) 그 출처의 저장소(localStorage · IndexedDB · 캐시 저장소 · 서비스 워커 …)를 지운 뒤(`Storage.clearDataForOrigin`) 탭을 닫는다. 쿠키만 지우면 토큰을 저장소에 두는 사이트는 로그인이 남기 때문이다. 다른 사이트의 로그인은 그대로다. 그 사이트에서 기다리는 클릭이 있으면 409, 브라우저에 닿지 못하면 502. 로그인 필요 표시는 바꾸지 않는다 (다음 일이 로그인 화면을 만나면 적힌다).

## 5. 데이터와 입구

**표** (스키마 `browser_tabs`, 마이그레이션은 `plugins/browser-tabs/migrations/`. 코어 표는 바꾸지 않고 값으로만 가리킨다):

| 표 | 칸 | 규칙 |
|---|---|---|
| `reads` | `url`, `status`(`requested` · `done` · `failed`), `title`, `body`, `error`, `requested_at`, `read_at`, `version` | http(s)만. 러너가 한 번만 남긴다 |
| `sites` | `name`, `start_url`, `origins[]`, `login_needed_at`, `created_at`, `updated_at`, `version` | 출처는 1~10개, `http(s)://호스트[:포트]`(경로 없음). 시작 주소는 출처 안. 고치고 지울 때 판을 본다. 로그인 필요 표시는 판을 올리지 않는다 |
| `clicks` | `task_id` · `site_id` · `runner_id`(값), `tab_id`, `page_url`, `page_title`, `role`, `name`, `nth`, `box`, `fingerprint`, `note`, `status`, `approval_id`, `reason`, `after_url`, `created_at` · `decided_at` · `clicked_at`, `version` | `held → approved → clicking → clicked · changed · unknown`, `held → dropped`, `approved · changed · unknown → manual`. 작업 하나에 열린 클릭(`held` · `approved` · `clicking`)은 하나(부분 유일 인덱스). 붙잡은 러너만 누른다. 2분 넘게 `clicking`이면 `unknown`(다시 누르지 않는다) |

코어 쪽은 `task.agents.scopes`의 `browse`, 일 종류 `browse`(위임 가능), 결재 동작 이름 `browser.site.publish` · `browser.site.login`(값)뿐이다 ([테이블설계](테이블설계.md) 6장).

**MCP** ([API설계](API설계.md) 4장): 러너(`run`) `browser_tab_pending` · `browser_tab_save`, 그 작업의 임대를 쥔 러너만 `browser_job` · `browser_shot_save` · `browser_login_needed` · `browser_click_hold`, 붙잡은 러너만 `browser_click_next` · `browser_click_save`. 에이전트(작업 토큰) `browser_sites`. `next_jobs`의 `browser`, `request_approval`의 `browser.site.publish`(대상 `browser_click`) · `browser.site.login`(대상 `browser_site`)은 러너가 작업 토큰으로 올린다.

**이벤트**: 패키지가 `task.task.requested`를 남긴다(`uses: task:request`). `task.approval.granted` · `revision_requested` · `rejected` · `cancelled`(클릭 결재 → `approved` · `dropped`, 로그인 결재의 수정 요청 → 표시 비우기)와 `task.task.changed`(실패 · 취소된 작업의 열린 클릭 닫기)를 받고, `plugin.browser_tabs.click_done { approvalId, outcome, error? }`를 남긴다.

결과 결재(2차 2단계)는 클릭 결재를 대화 회차의 결과 카드로 묶는다. 결재 줄의 모양(동작 · 대상 · 판)과 승인 이벤트가 같아 이 패키지는 그대로다. 로그인 필요는 결과가 아니라 바로 오는 결재로 남는다.

## 6. 안전장치와 남는 위험

| 막을 일 | 어디서 | 어떻게 |
|---|---|---|
| AI가 마지막 버튼을 누르는 것 | 스킬 · 러너 · 서버 | AI는 멈추고 `browser-stop.json`만 남긴다. 누르기는 결재 뒤 러너가 같은 탭 · 주소 · 지문 · 가장 위 요소일 때만 (`BrowserPages.press`). 다르면 누르지 않는다. 많아야 한 번 |
| 비공개가 브라우저 쪽 AI에게 가는 것 | 서버 | `browse`는 `read_all` · `write`와 함께 줄 수 없다. 브라우저 일을 맡기는 쪽도 그 권한이 없어야 한다. 재료는 지시문으로 |
| 둘러보기가 로그인 · 내부망에 닿는 것 | 러너 · 정책 | 일마다 새 빈 컨텍스트(쿠키 없음), 이름을 풀어 본 뒤 내부 · 사설 · 메타데이터 · CGNAT 주소를 막는 프록시. 정책이 이름을 한 번 더 막는다 |
| 조종 포트가 밖에 열리는 것 | 배포 구성 | CDP는 러너와 브라우저가 함께 쓰는 네트워크의 127.0.0.1에만. 밖으로 여는 포트가 없다 |
| 남이 화면을 보는 것 | 서버 | 콘솔 화면 · 세션 지우기 · 클릭 · 화면 API는 관리자만 |
| 다른 컨테이너가 조종 중계에 닿는 것 | 배포 구성 | 중계(9223)는 서버와 브라우저만 붙는 망(`browser`)에만. 웹 · DB · 일꾼은 그 망에 없다 |
| 다른 사이트로 가는 것 | 러너 | 허용 출처(`--allowed-origins`): 바로 이동 · `fetch` · 이미지는 막는다. 붙잡을 때 페이지가 허용 출처 안인지 서버가 다시 본다 |
| AI가 셸 · 다른 MCP를 쓰는 것 | 러너 | 셸은 없고, 격리 검사가 그 작업에서만 `playwright`를 허락한다. 작업 토큰은 cairn 설정에만 |
| 브라우저가 서버를 잡아먹는 것 | 배포 구성 | `mem_limit: 1g` (넘치면 브라우저만 죽는다). 로그는 10MB × 2 |

**남는 위험**
- **허용 출처는 경계가 아니다.** 허용한 사이트에서 나가는 리다이렉트는 막지 못했다 (시험, Playwright MCP 문서에도 "보안 경계가 아님"). 진짜 경계는 사이트 일에도 나가는 프록시를 거는 것이다 (다음 단계).
- **AI가 버튼을 누를 수 있다.** 허용 출처 안에서는 그 계정으로 할 수 있는 일을 다 할 수 있고, 막는 것은 스킬 지시뿐이다. 결재된 클릭은 "멈춘 버튼을 대신 누르는 길"이지 AI의 클릭을 막는 장치가 아니다. 자동화용 계정을 따로 쓰길 권한다.
- **역할 + 이름이 Playwright와 Chrome에서 다를 수 있다.** 다르면 붙잡지 못하거나(작업 실패) 바뀐 것으로 보여 누르지 않는다 (안전한 쪽으로 실패한다).
- **사이트 일이 관리자 탭을 옮길 수 있다.** Playwright MCP는 붙을 때 맨 앞 탭을 지금 탭으로 고른다. 스킬이 새 탭부터 열게 하고, 옮겨진 탭은 지문 검사가 "바뀜"으로 잡는다.
- **프로필이 하나다.** 사이트마다 나누지 않아 쿠키가 한 브라우저에 함께 있다 (요청은 허용 출처로만 나간다). 세션 지우기는 그 사이트의 호스트로 가는 쿠키만 지운다 (`.example.com` 쿠키는 그 아래 다른 사이트와 함께 지워진다).
- **관리자 로그인이 뚫리면 로그인된 브라우저가 넘어간다.** 콘솔 화면은 관리자 세션 하나로 열린다.
- **서버가 뚫리면 브라우저도 넘어간다.** 서버는 전용 망으로 조종 중계에 닿는다. 서버에는 이미 모든 데이터와 열쇠가 있어 새로 생기는 길은 아니다.
- **러너가 죽어도 둘러보기 창은 남지 않는다.** 프록시는 러너와 같은 프로세스라 함께 사라지고, 컨텍스트는 CDP 연결이 끊기면 Chrome이 지운다 (SIGKILL로 시험).
