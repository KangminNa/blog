# Cairn 서버 브라우저

로그인된 브라우저로 하는 일 두 가지(탭 읽기, 브라우저 에이전트)를 이 문서 하나에 모은다.
결정의 이유는 [기획서](기획서.md) 결정 기록(2026-11-08 · 2026-11-14 콘솔 화면), 기능 패키지의 틀은 [객체설계](객체설계.md) 12장, 배포 순서는 [README](../README.md) 6장.

## 1. 하는 일

| 일 | 흐름 | AI | 남는 것 |
|---|---|---|---|
| 탭 읽기 | 주인이 주소를 맡긴다 → 러너가 탭으로 열어 제목과 보이는 글자만 읽고 닫는다 | 없음 | `browser_tabs.reads` |
| 브라우저 에이전트 | 주인이 사이트에 일을 맡긴다 → 서버 러너의 AI가 그 사이트에서 편집하고, 발행 버튼 앞에서 결재를 올린다 → 주인이 화면에서 직접 발행한다 | 서버 러너의 구독 CLI(Claude · Codex) + Playwright MCP | 작업 · 결재 |

## 2. 원칙

- **AI는 러너에서만 브라우저를 움직인다.** 서버 본체에는 AI가 없다 (원칙 6). 서버는 관리자가 콘솔에서 화면을 보고 누르는 중계로만 브라우저에 붙는다 (2026-11-14, 3장).
- **발행 · 전송 · 삭제는 AI가 하지 않는다.** AI는 발행 직전에 멈추고 결재를 올린다. 주인이 화면에서 직접 누르고 결재를 "직접 발행했어요"로 닫는다 (원칙 7).
- **브라우저를 쓰는 에이전트는 비공개를 읽지 않는다.** 권한 `browse`는 `read_all` · `write`와 함께 줄 수 없다 (서버 규칙 + DB CHECK). `write`도 임시 글 본문과 소재 메모를 열기 때문이다 (`blog_get_post` · `basket_get`). 허용 출처가 경계가 아니라서(6장) "비공개 + 외부 내용 + 밖으로 보내기"에서 비공개를 뺀다. 그래서 채울 재료(제목 · 본문 · 태그)는 일을 맡길 때 지시문에 적는다.
- **CDP는 서버 밖으로 열지 않는다. 화면은 주인 확인 뒤에만 넘긴다.** 조종 중계(9223)는 서버와 브라우저만 붙는 망에 있고, 콘솔 화면 API는 관리자만 부른다.
- **브라우저 작업은 서버 러너만 받는다.** 내 컴퓨터 러너는 탭 읽기만 한다 (평소 쓰는 계정에 가까운 브라우저를 AI에게 맡기지 않는다).

## 3. 구성

```
주인 브라우저 ─https─ 앞단 프록시 ─┬─ 웹 · 콘솔 (운영 › 브라우저: 화면 그림 · 클릭 · 입력)
                                   ├─ Cairn 서버 (/api · /mcp)
                                   └─ (선택) /browser/ ─ 주인 확인 뒤 ─▶ neko 실시간 영상

Cairn 서버 ── 전용 망(browser) ── 조종 중계 9223 ─┐   (콘솔 화면: 관리자만)
서버 러너 ──MCP──▶ Cairn 서버                     │
   │ CDP 127.0.0.1:9222 (브라우저와 같은 네트워크) ▼
neko (Chromium + 로그인 프로필 볼륨) ── 사이트의 허용 출처 ──▶ 외부 사이트
```

- 서버 브라우저는 선택 구성 `docker-compose.browser.yml`이다. 켜면 서버 러너가 브라우저의 네트워크를 함께 쓴다(`network_mode: service:browser`). 러너에게 브라우저는 127.0.0.1이라 Chrome의 Host 검사를 중계 없이 지나고, CDP가 컨테이너 밖으로 나가지 않는다.
- **콘솔 화면 (기본, 2026-11-14):** 서버(`browser-tabs`의 `BrowserScreenGateway`)가 전용 망(`browser`)으로 브라우저 컨테이너의 조종 중계(`browser/cdp-relay.py`, 9223 → 127.0.0.1:9222)에 붙어 화면을 JPEG로 받고 클릭 · 스크롤 · 글자 · 키 · 이동 · 뒤로를 보낸다. 콘솔은 열려 있는 동안 1초마다 다시 그린다. HTTPS(443) 하나로 끝나 UDP · 공인 IP · 앞단 프록시 설정이 필요 없다.
  - 전용 망에는 브라우저(와 그 네트워크를 함께 쓰는 서버 러너)와 서버만 붙는다. 웹 · DB · 일꾼은 9223에 닿지 않는다.
  - Chrome은 Host가 이름이면 거절해서(`Host header is specified and is not an IP address or localhost`) 서버는 서비스 이름 `browser`를 IP로 풀어 붙는다.
  - 화면 API는 관리자만 부른다. 입력한 글자(로그인 비밀번호일 수 있다) · 주소 · 화면은 어디에도 남기지 않는다. 주소 이동은 http(s)만.
- **실시간 영상 (선택):** neko 화면 페이지는 이 서버 안(127.0.0.1:4100)에서만 열리고, 앞단 프록시가 `/browser/`로 넘긴다. 영상은 UDP 52000 하나(`NEKO_WEBRTC_UDPMUX`, 기본은 이 서버 안에서만. 밖에 열 때 `BROWSER_UDP_BIND` · `CAIRN_PUBLIC_IP`). neko 비밀번호(`CAIRN_BROWSER_PASSWORD`)로 한 겹 더 막는다.
- 앞단 프록시는 README의 예시가 Caddy(`forward_auth`)다. 요청마다 주인 확인을 물을 수 있는 프록시면 된다 (nginx `auth_request`, Traefik `ForwardAuth`). 영상을 쓰지 않으면 넣지 않는다.
- 내 컴퓨터에서는 러너 전용 Chrome 프로필을 `--remote-debugging-port`로 띄우고 `CAIRN_BROWSER_URL`을 주면 탭 읽기를 한다 (`apps/runner/.env.example`).

## 4. 흐름

### 탭 읽기

1. 주인: `POST /api/p/browser-tabs/reads { url }` → `reads`에 `requested`.
2. 러너의 `TabReader`(일과 따로 돎): `browser_tab_pending`으로 받는다. 없으면 15초, 패키지가 꺼져 있으면 5분 뒤 다시 묻는다.
3. `BrowserTabs`: 새 탭 → 다 뜨면(30초) 1.5초 뒤 제목과 `innerText` → 탭 닫기.
4. `browser_tab_save`로 남긴다. 페이지 문제(열지 못함 · 안 뜸)는 이유를 남기고, 브라우저에 닿지 못하면 남기지 않고 기다렸다 다시 한다. 로그에는 주소의 호스트만.

### 브라우저 에이전트

1. 주인: 사이트를 등록하고(이름 · 시작 주소 · 허용 출처), 화면에서 그 사이트에 로그인한다.
2. 주인: 사이트에서 "일 맡기기" → 패키지가 `task.task.requested`(종류 `browse`, 그때의 사이트 값을 `payload.site`에)를 남긴다. 담당을 비우면 `browse` 권한이 있는 에이전트가 맡는다.
3. 서버: `browse` 작업은 `next_jobs`에서 `browser: true`를 알린 러너에게만 빌려 준다.
4. 서버 러너: 브라우저에 닿는지 묻고(3초), 닿지 못하면 돌려주고(`release_job`) 기다린다. 닿으면 AI CLI에 cairn MCP와 Playwright MCP(`--cdp-endpoint`, `--allowed-origins`)를 붙여 띄운다. 스킬은 `cairn-browse`.
5. AI: 사이트에서 편집기를 채우고, 발행 버튼 앞에서 `request_approval { action: "browser.site.publish", target_kind: "browser_site", target_id: 사이트 id, target_version: 사이트 판 }`을 올리고 끝낸다.
6. 주인: 콘솔의 브라우저 화면에서 직접 발행하고, 결재에서 "직접 발행했어요"(승인)를 누른다. 고칠 게 있으면 "수정 요청"으로 돌려보낸다.
7. 패키지: `task.approval.granted`를 받아(이벤트로 도는 동작 `ConfirmPublish`) 자기 동작이면 결과(`approvalId`, `outcome: done`)를 남긴다 → 코어가 작업을 끝낸다.

## 5. 데이터와 입구

**표** (스키마 `browser_tabs`, 마이그레이션은 `plugins/browser-tabs/migrations/`):

| 표 | 칸 | 규칙 |
|---|---|---|
| `reads` | `url`, `status`(`requested` · `done` · `failed`), `title`, `body`, `error`, `requested_at`, `read_at`, `version` | http(s)만. 러너가 한 번만 남긴다 |
| `sites` | `name`, `start_url`, `origins[]`, `created_at`, `updated_at`, `version` | 출처는 1~10개, `http(s)://호스트[:포트]`(경로 없음). 시작 주소는 출처 안. 고치고 지울 때 판을 본다 |

코어 쪽은 `task.agents.scopes`의 `browse`뿐이다 ([테이블설계](테이블설계.md) 6장).

**REST** `/api/p/browser-tabs/…` (모두 주인만):

| 경로 | 입력 | 출력 |
|---|---|---|
| `GET /reads` · `POST /reads` | `{ url }` | `{ reads: [{ id, url, status, title, preview, error, requestedAt, readAt }] }` |
| `GET /sites` | — | `{ sites: [{ id, name, startUrl, origins, version, updatedAt }] }` |
| `POST /sites` | `{ name, startUrl, origins[] }` | 사이트 |
| `PATCH /sites/:id` | `{ version, name?, startUrl?, origins? }` | 사이트 (판이 다르면 409) |
| `DELETE /sites/:id` | `{ version }` | `{ sites }` |
| `POST /sites/:id/tasks` | `{ requestId, instruction, agentId? }` | `{ requestId }` (작업은 코어가 곧 만든다) |
| `GET /viewer` | — | `{ ok: true }`. 앞단 프록시가 실시간 영상을 넘기기 전에 묻는 주인 확인 |
| `GET /screen?tab=` | 탭 id(없으면 맨 앞 탭) | `{ tabs: [{ id, title, url }], tab, image(JPEG base64), width, height }`. 브라우저에 닿지 못하면 502 |
| `POST /screen/control` | `{ tab, type, … }`: `click { x, y }` · `scroll { x, y, dy }` · `text { text }` · `key { key }`(Enter · Tab · Backspace · Escape · 화살표) · `navigate { url }`(http(s)) · `back` · `activate` | `{ ok: true }`. 좌표는 `width × height` 기준 CSS 픽셀 |

**MCP**: `browser_tab_pending` · `browser_tab_save`(`run`), `next_jobs`의 `browser`, `request_approval`의 `browser.site.publish`. [API설계](API설계.md) 4장.

**이벤트**: 패키지가 `task.task.requested`를 남긴다(`uses: task:request`). `task.approval.granted`를 받아 `plugin.browser_tabs.publish_confirmed { approvalId, outcome }`를 남긴다(`uses: event:task.approval.granted`).

## 6. 안전장치와 남는 위험

| 막을 일 | 어디서 | 어떻게 |
|---|---|---|
| 비공개가 브라우저 쪽 AI에게 가는 것 | 서버 | `browse`는 `read_all` · `write`와 함께 줄 수 없다. 재료는 지시문으로 |
| 조종 포트가 밖에 열리는 것 | 배포 구성 | CDP는 러너와 브라우저가 함께 쓰는 네트워크의 127.0.0.1에만 |
| 남이 화면을 보는 것 | 서버 · 앞단 프록시 · neko | 콘솔 화면 API는 관리자만. 실시간 영상은 주인 확인(`/viewer`) 뒤에만 넘기고, neko 비밀번호를 한 번 더 |
| 다른 컨테이너가 조종 중계에 닿는 것 | 배포 구성 | 중계(9223)는 서버와 브라우저만 붙는 망(`browser`)에만. 웹 · DB · 일꾼은 그 망에 없다 |
| 다른 사이트로 가는 것 | 러너 | 허용 출처(`--allowed-origins`): 바로 이동 · `fetch` · 이미지는 막는다 |
| AI가 셸 · 다른 MCP를 쓰는 것 | 러너 | 셸은 없고, 격리 검사가 그 작업에서만 `playwright`를 허락한다. 작업 토큰은 cairn 설정에만 |
| 브라우저가 서버를 잡아먹는 것 | 배포 구성 | `mem_limit: 1g` (넘치면 브라우저만 죽는다) |

**남는 위험**
- **허용 출처는 경계가 아니다.** 허용한 사이트에서 나가는 리다이렉트는 막지 못했다 (시험, Playwright MCP 문서에도 "보안 경계가 아님"). 허용한 사이트에 열린 리다이렉트가 있으면 그 사이트의 내용이 밖으로 나갈 수 있다. 진짜 경계는 브라우저의 나가는 프록시(다음 단계)다.
- **AI가 발행을 누를 수 있다.** 허용 출처 안에서는 그 계정으로 할 수 있는 일을 다 할 수 있고, 막는 것은 스킬 지시뿐이다. 자동화용 계정을 따로 쓰길 권한다.
- **프로필이 하나다.** 사이트마다 나누지 않아 쿠키가 한 브라우저에 함께 있다 (요청은 허용 출처로만 나간다).
- **관리자 로그인이 뚫리면 로그인된 브라우저가 넘어간다.** 콘솔 화면은 관리자 세션 하나로 열린다 (실시간 영상은 앞단 프록시의 주인 확인과 neko 비밀번호 두 겹).
- **서버가 뚫리면 브라우저도 넘어간다.** 서버는 전용 망으로 조종 중계에 닿는다. 서버에는 이미 모든 데이터와 열쇠가 있어 새로 생기는 길은 아니다.

## 7. 시험 결과 (2026-11-08, neko · Chromium 156)

| 시험 | 결과 | 고친 것 |
|---|---|---|
| 러너 → 브라우저 (CDP) | 같은 네트워크의 컨테이너가 127.0.0.1:9222로 붙고, 러너 코드(`BrowserTabs`)가 그대로 읽었다 | 기본 정책 `DeveloperToolsAvailability: 2`가 CDP를 막아 정책 파일로 바꿈 |
| 로그인 유지 | 재시작 · 새 컨테이너 · 로그인 직후 바로 재시작 모두 유지 | 기본 `--bwsi`(게스트)와 프로필의 "세션에만 쿠키"(`cookies: 4`) 때문에 끄면 지워졌다 → `--bwsi` 빼기, 정책 `DefaultCookiesSetting: 1`, `--password-store=basic` |
| 허용 출처 (Playwright MCP 0.0.83) | 바로 이동 · `fetch` · 이미지: 다른 출처에 도착 0번. 리다이렉트: 1번 도착 | 가드레일로만 쓰고 비공개를 뺐다 |
| 콘솔 안 화면 | `/browser/` 아래로 앞부분을 떼어 넘기면 iframe 안에서 영상(1280×720)이 나온다. neko는 iframe을 막는 헤더가 없고 주소를 상대 경로로 만든다 | — |
| 메모리 · CPU | 쉬면 약 250MB, 화면을 보면 약 290MB · 코어 하나의 30~45% (가벼운 페이지) | 한도 1GB |

실행 옵션과 정책은 `browser/`에 있고, 빌드한 이미지로 같은 시험(읽기 · 로그인 · 재시작 뒤 유지)을 다시 통과했다.
Steel Browser는 이 환경에서 이미지를 받을 수 없어 시험하지 못했다.

**콘솔 화면 시험 (2026-11-14)**

| 시험 | 결과 | 고친 것 |
|---|---|---|
| 화면 그리기 · 입력 (Chromium 153, 화면 있는 모드 + Xvfb) | 캡처(JPEG, 약 8KB) · 클릭 · 한글 입력(`Input.insertText`) · Enter로 폼 보내기 · 스크롤 · 이동 · 뒤로 모두 됨. Node의 웹소켓이 Origin을 보내지 않아 `--remote-allow-origins` 없이 붙는다 | — |

| 빌드한 이미지 + 중계 (neko · Chromium 156) | 시험용 망의 다른 쪽에서 9223으로 붙어 캡처 · 이동 · 클릭 · 한글 입력까지 됨. Chrome이 뜨는 데 이 환경에서 30초쯤 걸렸다 | 중계를 `socat`(빌드 때 apt로 받음)에서 이미지에 있는 python3(`cdp-relay.py`)로 바꿨다: 빌드할 때 내려받을 것이 없다 |

**아직 확인하지 않은 것**

- 콘솔의 브라우저 메뉴 화면 (타입 검사만. 화면 칸은 서버 API까지 시험했다).
