# Cairn 테이블 설계 (MVP · 2판)

> 작성 2026-10-03 · 상태: 초안 (검토 중)
> 근거: [MVP-기획서.md](MVP-기획서.md), [기획서.md](기획서.md) 4장(CRUD·동시성)·7장(데이터 형식)
> 1판에서 바뀐 점: 확장성 설계(공간·사용자·종류 목록·모델별 임베딩·공통 파일)와 테이블별 인덱스 근거 추가. 로그 월별 분할은 2026-10-10에 하지 않기로 함

## 0. 공통 규칙

| 항목 | 규칙 |
|---|---|
| DB | Postgres 17+, 확장 `pg_bigm`(한국어 키워드), `vector`(pgvector), `pgcrypto` |
| 스키마 | **모듈 = 스키마.** `platform`(공통: 파일·중복 방지·outbox·일거리·알림·임베딩 모델), `account`(공간·사람·기기·로그인), `vault`(세션·그래프·제안·변경 기록), `blog`·`work`(글·글감 상자, blog 모듈 소유), `mcp`(읽기 기록). 지도는 `apps/server/modules.json` |
| 모듈 사이 | **외래키를 두지 않는다** (2026-10-08, 마이그레이션 `module_schemas`). 다른 모듈의 행을 가리키는 열(`space_id`, `device_id`, `blob_hash` 등)은 값만 갖고, 유효성은 주인 모듈의 코드가 지킨다. 같은 모듈 안의 외래키는 그대로 |
| 독립 원칙 | **`vault`와 `blog` 사이에는 외래키가 없다** (위의 모듈 사이 규칙의 한 경우). 둘을 오가는 참조는 `종류 + ID`의 느슨한 참조이고, 방문자에게 드러나지 않는다 |
| 기본키 | `uuid` (UUIDv7, 앱에서 생성. 시간순이라 B-tree 끝에만 쌓여 쓰기에 유리). 로그성 테이블은 `(created_at, id bigint)` |
| 공간 | 사용자 데이터 테이블은 모두 `space_id uuid NOT NULL`을 가진다. MVP는 공간 하나. 복합 인덱스는 `space_id`를 맨 앞에 둔다 |
| 시각 | 모두 `timestamptz` |
| 삭제 | 사용자 데이터는 `deleted_at` + `purge_after`(휴지통). 조회 인덱스는 `WHERE deleted_at IS NULL` 부분 인덱스 |
| 낙관적 잠금 | 사람이 고치는 행에 `version int NOT NULL DEFAULT 1` |
| 행위자 | `actor_type text`(`user`·`device`·`ai`·`system`) + `actor_id uuid`. 사람이 읽는 표기는 화면에서 조립 |
| 열거형 | 자주 늘어날 종류는 **목록 테이블**(외래키), 거의 안 바뀌는 상태값은 `text + CHECK` |
| 확장 열 | 주요 엔티티에 `meta jsonb NOT NULL DEFAULT '{}'`. 새 도구·어댑터의 추가 정보, 가져온 md의 모르는 frontmatter를 보관 |
| 불변 테이블 | `session_revisions`, `post_revisions`는 INSERT만 (트리거로 UPDATE·DELETE 차단, 영구 삭제 일꾼만 예외) |

## 1. 확장성 설계

| 나중에 생길 수 있는 일 | 지금 해 두는 것 | 그때 할 일 |
|---|---|---|
| 팀 블로그, 공식 호스팅(여러 사람) | 모든 데이터에 `space_id`, 사용자·역할 테이블 | 공간 추가, 행 수준 보안(RLS) 켜기 |
| 관리자 여러 명 | `account.users` + `account.space_members(role)` | 역할 추가 |
| 새 점 종류 (문서, 링크, 사람 등) | `vault.node_kinds` 목록 + 점 상위 테이블 `nodes` | 목록에 행 추가 + 상세 테이블 하나 |
| 새 연결 종류 (하위 주제, 이어지는 작업 등) | `vault.edge_kinds` 목록 (방향 여부 포함) | 목록에 행 추가만 |
| 임베딩 모델 교체·여러 모델 | `platform.embedding_models` 목록, 차원을 고정하지 않은 `vector` 열 + 모델별 부분 인덱스 | 모델 행 추가 → 다시 계산 → 인덱스 추가 |
| 세션 노트 칸 구성 변경 | 판마다 `sections_schema int` | 새 버전 파서 추가, 옛 판은 그대로 |
| 새 AI 도구(세션 소스) | `tool text` + `meta jsonb` | 어댑터만 추가 |
| S3 등 다른 파일 저장소 | 공통 `platform.blobs`(내용 해시)에 `storage_backend` | 백엔드 추가, 옮기기 작업 |
| 그래프 보기 여러 개 (방문자 기본·주인 기본·저장한 보기) | `vault.graph_views`(설정 `settings`) + `node_layout(view_id, node_id)` | 보기 행 추가, 설정 항목은 `GraphView` 객체에 추가 |
| 글감 상자 여러 개 | `work.baskets` + `basket_items` | MVP는 기본 상자 하나, 화면만 추가 |
| 글 다국어 | `blog.posts.lang` | 번역 글 연결 테이블 |
| 댓글·반응 | 둘 다 플러그인 (자체 저장이면 플러그인 스키마). 공감(돌 얹기)은 코어 MVP에서 뺐다 (2026-10-10). 지금 있는 `posts.stone_count`·`blog.stone_log`는 플러그인을 만들 때 정리 | 플러그인 추가 |
| 로그가 수억 건 | 시각 BRIN 인덱스 + 날짜 기준 삭제 (분할 안 함, 1인 블로그는 수백만 행도 충분) | 그때 월별 분할로 옮김 |

## 2. `account` · `platform` · `mcp` 스키마 (옛 `app`)

> 처음에는 한 `app` 스키마였고, 2026-10-08에 주인 모듈별로 나눴다. 아래의 `→` 표시 중 다른 모듈을 가리키는 것은 외래키가 아니라 값 참조다. `edit_leases`는 `vault.edit_leases`(세션·주제)와 `blog.edit_leases`(글)로 나뉘었다.


```sql
-- 공간과 사람 ---------------------------------------------------------------
account.spaces(
  id uuid PK, slug text UNIQUE, name text, version int NOT NULL DEFAULT 1, created_at timestamptz)
  -- 설치됐다 = 주인이 있다. 설치 코드는 서버 키에서 만들고 저장하지 않는다 (M1 A)

account.users(
  id uuid PK, login text UNIQUE NOT NULL CHECK (login ~ '^[a-z0-9_-]{3,40}$'),   -- 아이디
  password_hash text,                     -- "scrypt$N$r$p$salt$hash". 원문은 어디에도 두지 않는다
  password_changed_at timestamptz, display_name text, avatar_url text, email text,
  created_at timestamptz)

account.login_links(                     -- 로그인 플러그인(GitHub 등)으로 들어온 외부 계정과 주인의 연결
  method text, subject text,              -- 로그인 방법, 그 서비스의 계정 id
  user_id uuid → users ON DELETE CASCADE, label text, created_at timestamptz,
  PRIMARY KEY (method, subject))         -- 연결된 계정으로만 주인 로그인이 된다

account.space_members(
  space_id uuid → spaces, user_id uuid → users,
  role text CHECK (role IN ('owner','editor','viewer')),  -- MVP는 owner 한 명. UNIQUE (space_id) WHERE role = 'owner'
  created_at timestamptz,
  PRIMARY KEY (space_id, user_id))

account.settings(
  space_id uuid → spaces, key text, value jsonb NOT NULL, updated_at timestamptz,
  PRIMARY KEY (space_id, key))           -- blog.description, site.url, github.client_id · github.url · github.api_url, blog.style_guide, notify.* …

account.secrets(

-- 기기와 인증 ---------------------------------------------------------------
account.devices(
  id uuid PK, space_id uuid NOT NULL, user_id uuid → users,
  name text NOT NULL, scopes text[] NOT NULL,          -- upload · read_public · read_all · tidy · write
  is_primary_tidy boolean DEFAULT false,
  meta jsonb DEFAULT '{}',                -- clientId, clientName (어느 AI 도구로 연결했는지)
  version int NOT NULL DEFAULT 1, created_at, last_seen_at timestamptz, last_ip inet, revoked_at timestamptz)

account.oauth_clients(client_id text PK, space_id uuid, client_name text, redirect_uris text[], created_at)
account.oauth_codes(code_hash text PK, client_id text, redirect_uri text, device_draft jsonb, code_challenge text,
                expires_at timestamptz, used_at timestamptz)   -- 5분, 한 번만. 기기는 토큰으로 바꿀 때 만든다
account.oauth_tokens(
  id uuid PK, device_id uuid → devices, client_id text, kind text CHECK (kind IN ('access','refresh')),
  token_hash text UNIQUE, scopes text[], expires_at, revoked_at, created_at)
account.device_tokens(
  id uuid PK, device_id uuid → devices, token_hash text UNIQUE, prefix text,
  expires_at, revoked_at, created_at)
account.web_sessions(
  id uuid PK, user_id uuid → users, token_hash text UNIQUE, ip inet, user_agent text,

-- 공통 파일 (내용 주소) -------------------------------------------------------
platform.blobs(
  hash text PK,                          -- sha256

vault.edit_leases(
  target_kind text, target_id uuid, space_id uuid,

  PRIMARY KEY (target_kind, target_id))

platform.notifications(
```

## 3. `vault` 스키마

### 그래프 = 대표 하나 + 선 (2026-10-10, 마이그레이션 `graph_addresses`)

| 점 | 대표 (열 하나) | 대표가 비어 있으면 |
|---|---|---|
| 세션 | `sessions.wiki_id` → wiki | 도착 구역 (정리 전) |
| wiki | `wikis.category_id` → 카테고리 | 미분류 |
| 글 (blog) | `posts.main_wiki_id` (값, 외래키 없음). vault는 사본 `post_marks.main_wiki_id`로 안다 | 그래프에 나오지 않음 |

- 옮기기·합치기·지우기는 대표 값 하나를 바꾸는 일이다. 아래 데이터는 부모 id만 갖고 있어서 위가 바뀌어도 그대로다.
- "미분류"와 "도착 구역"은 행이 아니라 `NULL`이다. 지우거나 이름을 바꿀 수 없다.
- 대표 밖 연결은 `edges`의 선: `material`(세션 → 다른 wiki), `link`(wiki ↔ wiki), `similar`(계산값). 글 → 다른 wiki는 `blog.post_wiki_refs`.
- **글 자리 사본** (2026-10-10, 마이그레이션 `graph_views_post_marks`): vault는 blog를 읽지 않는다. blog가 글 이벤트(발행·수정·내림·삭제)를 보내면 vault의 Handler가 `vault.post_marks`에 제목·상태·대표 wiki·참고 wiki를 적어 두고, 그래프는 이것으로 글 점과 선을 그린다. 이벤트 순서가 바뀌어도 `post_version`이 큰 것만 반영한다.
- **지우기 규칙**: 부모를 지워도 자식은 지워지지 않는다. 카테고리를 영구 삭제하려면 먼저 wiki를 옮겨야 하고(`RESTRICT`), wiki가 영구 삭제되면 세션은 도착 구역으로 간다(`SET NULL`). `CASCADE`는 같은 점의 일부(상세 행, 판, 그 점의 선, 검색 조각)에만 쓴다. 세션(raw)은 사람이 그 세션을 직접 지울 때만 휴지통으로 간다.

```sql
vault.node_kinds(name text PK, detail_table text, description text)      -- category, wiki, session
vault.edge_kinds(
  name text PK,                           -- material, link, similar (+ 나중에 follows …). 소속은 대표 열로
  directed boolean NOT NULL,              -- 방향 없는 종류는 (src < dst)로 정렬해 저장
  ai_creatable boolean NOT NULL, description text)

vault.nodes(
  id uuid PK, space_id uuid NOT NULL,
  kind text NOT NULL → node_kinds(name),
  created_at timestamptz, deleted_at timestamptz, purge_after timestamptz)

vault.sessions(
  node_id uuid PK → nodes(id),
  space_id uuid NOT NULL,
  device_id uuid NOT NULL,                -- → account.devices
  tool text NOT NULL, source_session_id text NOT NULL, project text,
  visibility text NOT NULL DEFAULT 'private' CHECK (visibility IN ('private','public')),
  head_revision_id uuid,                  -- → session_revisions (DEFERRABLE)
  held_revision_id uuid,                  -- 편집 중이라 보류된 새 원본
  version int NOT NULL DEFAULT 1,
  pinned_sections text[] NOT NULL DEFAULT '{}',
  wiki_id uuid → wikis ON DELETE SET NULL,  -- 대표 wiki. 비어 있으면 도착 구역
  head_title text, head_summary text, head_text text,   -- 찾기용 복사본
  revision_count int NOT NULL DEFAULT 0,
  started_at, last_revision_at timestamptz,
  meta jsonb NOT NULL DEFAULT '{}',
  UNIQUE (space_id, device_id, tool, source_session_id))

vault.session_revisions(                  -- INSERT만
  id uuid PK, session_id uuid NOT NULL → sessions(node_id),
  seq int NOT NULL,
  kind text CHECK (kind IN ('origin','human','merge')),
  parent_ids uuid[], base_revision_id uuid,
  body_md text NOT NULL,
  sections jsonb NOT NULL, sections_schema int NOT NULL DEFAULT 1, section_hashes jsonb NOT NULL,
  content_hash text NOT NULL, redactions jsonb,
  actor_type text, actor_id uuid, created_at timestamptz,
  UNIQUE (session_id, seq))

vault.attachments(                        -- 세션 판 ↔ 파일
  revision_id uuid → session_revisions, blob_hash text → platform.blobs,
  name text, caption text, position int,
  visibility text NOT NULL DEFAULT 'private',
  scan_status text CHECK (scan_status IN ('pending','clean','flagged')), scan_flags jsonb,
  PRIMARY KEY (revision_id, blob_hash))

vault.categories(                         -- 옛 topics. 사람이 만들고 AI는 제안만
  node_id uuid PK → nodes(id), space_id uuid NOT NULL,
  name text NOT NULL, slug text NOT NULL, color text,
  description text,                       -- 분류 기준. AI 정리 스킬이 읽음
  sort int NOT NULL DEFAULT 0,
  origin text CHECK (origin IN ('ai','human')), pinned boolean NOT NULL DEFAULT false,
  version int NOT NULL DEFAULT 1, meta jsonb NOT NULL DEFAULT '{}',
  UNIQUE (space_id, slug))

vault.wikis(                              -- 여러 세션을 모아 쓴 정리 문서. 본문은 판으로 쌓는다
  node_id uuid PK → nodes(id), space_id uuid NOT NULL,
  category_id uuid → categories ON DELETE RESTRICT,   -- 대표 카테고리. 비어 있으면 미분류
  title text NOT NULL, slug text NOT NULL,
  visibility text NOT NULL DEFAULT 'private' CHECK (visibility IN ('private','public')),
  origin text CHECK (origin IN ('ai','human')),
  head_revision_id uuid,                  -- → wiki_revisions (DEFERRABLE)
  pinned_sections text[] NOT NULL DEFAULT '{}',   -- 사람이 고친 칸. AI가 바꾸려 하면 검토로
  head_text text, revision_count int NOT NULL DEFAULT 0,   -- 찾기용 복사본
  version int NOT NULL DEFAULT 1, created_at, updated_at timestamptz, meta jsonb,
  UNIQUE (space_id, slug))

vault.wiki_revisions(                     -- INSERT만. AI가 고칠 때마다 새 판
  id uuid PK, wiki_id uuid NOT NULL → wikis ON DELETE CASCADE,
  seq int NOT NULL,
  kind text CHECK (kind IN ('ai','human','merge')),
  base_revision_id uuid → wiki_revisions,  -- 보고 고친 판 (칸 단위 합치기의 기준)
  change_set_id uuid → change_sets,       -- 어느 변경 묶음에서 나왔는지
  body_md text NOT NULL,
  sections jsonb NOT NULL,                -- md 제목(##) 단위 칸: [{ key, title, body }]
  section_hashes jsonb NOT NULL, content_hash text NOT NULL,
  actor_type text, actor_id uuid, created_at timestamptz,
  UNIQUE (wiki_id, seq))

vault.wiki_aliases(                       -- 합쳐져 없어진 wiki의 옛 주소. 글의 참고 wiki·링크가 깨지지 않게
  old_id uuid PK,                         -- 영구 삭제됐을 수 있어 외래키 없음
  space_id uuid NOT NULL, new_id uuid NOT NULL → wikis ON DELETE CASCADE,
  change_set_id uuid → change_sets, created_at timestamptz)

vault.edges(
  id uuid PK, space_id uuid NOT NULL,
  src uuid NOT NULL → nodes(id), dst uuid NOT NULL → nodes(id),
  kind text NOT NULL → edge_kinds(name),
  weight real, origin text CHECK (origin IN ('ai','human')), pinned boolean NOT NULL DEFAULT false,
  version int NOT NULL DEFAULT 1,
  actor_type text, actor_id uuid, created_at timestamptz,
  deleted_at timestamptz, deleted_by_type text,   -- 사람이 지운 연결은 행을 남겨 AI가 다시 못 만듦
  CHECK (src <> dst),
  UNIQUE (src, dst, kind))

-- 변경 묶음과 검토 규칙 (2026-10-10, 마이그레이션 change_sets_wiki_revisions) ---------------------
-- git처럼: 정리 결과 한 번 = 묶음(커밋) 하나. 변경마다 검토 규칙을 대 보고 바로 합치기 / 검토 / 거부.
-- 승인함 = 검토를 기다리는 change_ops. 대정리 = 작성 중인 묶음(브랜치). 되돌리기 = 새 묶음(revert).
-- 관리 화면 편집도 묶음(kind = human)으로 남긴다. 규칙은 거치지 않고 바로 합쳐진다.
vault.change_sets(
  id uuid PK, space_id uuid NOT NULL,
  kind text CHECK (kind IN ('tidy','reorg','human','revert','system')),
  status text CHECK (status IN ('open','review','done')),   -- open: 대정리 작성 중, review: 검토 기다림
  actor_type text, actor_id uuid, job_id uuid,
  message text NOT NULL DEFAULT '',       -- 왜 바꾸는지
  base_graph_version bigint,              -- 대정리가 갈라진 기준점
  op_count int, reverted_by uuid → change_sets, version int,
  created_at, submitted_at, closed_at timestamptz)

vault.change_ops(                         -- 묶음 안의 변경 하나 (요청한 일). 실제로 바뀐 행은 changes에
  change_set_id uuid → change_sets, seq int,
  op text,                                -- wiki.revise · session.assign · category.merge … (서버의 ChangeOp)
  target_kind text CHECK (target_kind IN ('session','wiki','category','edge')), target_id uuid,
  base_version int, payload jsonb,
  verdict text CHECK (verdict IN ('merge','review','reject')),   -- 비어 있으면 판정 전
  rule text,                              -- 걸린 규칙
  status text CHECK (status IN ('pending','applied','waiting','approved','declined','rejected','superseded')),
  reason text, decided_at timestamptz, decided_by uuid,
  PRIMARY KEY (change_set_id, seq))

vault.review_rules(                       -- 주인이 고른 규칙 값만. 규칙의 뜻은 서버의 ReviewRule. 행이 없으면 기본값
  space_id uuid, key text,                -- add · edit_own · human_owned · structure · publish · delete · large_set
  action text CHECK (action IN ('merge','review','reject')), value int,
  updated_at timestamptz, updated_by uuid,
  PRIMARY KEY (space_id, key))

vault.project_rules(
  space_id uuid, project text, default_visibility text, collect boolean, updated_at,
  PRIMARY KEY (space_id, project))

vault.graph_views(                        -- 그래프 보기 (옛 layouts). 보기 설정 + 점 좌표
  id uuid PK, space_id uuid, name text,
  audience text CHECK (audience IN ('public','owner')),   -- public: 방문자에게 보일 수 있는 보기
  settings jsonb NOT NULL DEFAULT '{}',   -- 색 기준, 보일 점·선 종류, 거리 등 (서버의 GraphView 객체가 읽음)
  is_default boolean NOT NULL DEFAULT false,              -- 대상마다 하나 (부분 UNIQUE)
  version bigint, built_at, updated_at timestamptz,
  UNIQUE (space_id, name))
vault.node_layout(
  view_id uuid → graph_views, node_id uuid → nodes, x real, y real, pinned boolean,
  PRIMARY KEY (view_id, node_id))

vault.graph_snapshots(
  id bigint IDENTITY PK, space_id uuid, view_id uuid, audience text CHECK (audience IN ('public','owner')),
  version bigint, blob_hash text, node_count int, edge_count int, built_at timestamptz)

vault.post_marks(                         -- 글 자리 사본. blog 이벤트로 채움 (외래키는 vault 안쪽만)
  post_id uuid PK,                        -- blog.posts.id (값)
  space_id uuid NOT NULL, title text, slug text,
  status text CHECK (status IN ('draft','published')),   -- 방문자 그래프에는 published만
  main_wiki_id uuid → wikis ON DELETE SET NULL,
  ref_wiki_ids uuid[] NOT NULL DEFAULT '{}',
  post_version int NOT NULL, updated_at timestamptz)

vault.chunks(                             -- 검색 조각 (현재 판만 유지)
  id uuid PK, space_id uuid NOT NULL,
  session_id uuid NOT NULL → sessions(node_id), revision_id uuid NOT NULL,
  section text, chunk_no int, text text NOT NULL,
  UNIQUE (revision_id, section, chunk_no))

vault.chunk_embeddings(                   -- 모델별 벡터
  chunk_id uuid → chunks ON DELETE CASCADE,
  model_id smallint → platform.embedding_models,
  embedding vector NOT NULL,              -- 차원 미고정. 인덱스는 모델별로 차원을 지정
  PRIMARY KEY (chunk_id, model_id))
```

## 6. 인덱스

원칙
- **모든 외래키 열에 인덱스** (Postgres는 자동으로 만들지 않음. 삭제·조인이 느려짐)
- 조회는 대부분 휴지통 제외라서 **`WHERE deleted_at IS NULL` 부분 인덱스**
- 여러 공간을 대비해 **`space_id`를 복합 인덱스 맨 앞**에
- 쓰기가 많은 판·로그 테이블은 **인덱스를 최소로**
- 목록 화면은 필요한 열을 `INCLUDE`로 덮어 테이블을 읽지 않게
- 로그의 시각 인덱스는 **BRIN**(아주 작고 순차 데이터에 적합). 분할은 하지 않는다

| 테이블 | 인덱스 | 쓰는 곳 |
|---|---|---|
| `account.devices` | `(space_id) WHERE revoked_at IS NULL` | 기기 목록 |
| `account.oauth_tokens` | `UNIQUE (token_hash)`, `(device_id)`, `(expires_at) WHERE revoked_at IS NULL` | 매 요청 인증, 만료 정리 |

## 7. 핵심 동작별 트랜잭션

| 동작 | 순서 (한 트랜잭션) |
|---|---|
| **세션 올리기** | `idempotency` 자리 잡기(같은 요청이면 처음 결과) → 대화 자리 잠금(`pg_advisory_xact_lock`, 세션이 없어도) → 세션 `SELECT … FOR UPDATE`(없으면 `nodes`·`sessions` INSERT) → 내용 해시가 이미 있으면 판 없이 끝(`unchanged`) → `session_revisions` INSERT → 편집 임대가 없으면 `head_revision_id` 갱신(`version` 비교), 있으면 `held_revision_id`(편집 임대는 관리 화면 편집 단계부터) → `outbox(vault.session.saved)` → `idempotency` 결과 기록. 정리 일거리(`jobs`)는 M3에서 이 이벤트를 받아 만든다 |
| **일거리 빌리기** | `jobs`에서 `ready` + 편집 임대 없는 대상 `FOR UPDATE SKIP LOCKED LIMIT n` → `leased` |
| **정리 결과 제출** | `idempotency` → `change_sets` INSERT → 대상 잠금 → 편집 임대·`base_version` 검사 → 변경마다 검토 규칙 판정(`change_ops`) → 바로 합칠 것은 엔티티로 적용 + `changes`, 검토는 `waiting`, 거부는 이유 → `jobs` 완료 → `outbox` |
| **관리 모드 저장** | 임대 확인 → `version` 비교 → `human` 판 INSERT(보류 판과 칸 단위 합치기) → `head_revision_id` 갱신, `pinned_sections` 추가 → 임대 해제 → `changes`·`outbox` |
| **그래프 편집** | `change_sets`(kind = human) → 대상 잠금 → 변경(`origin='human'`, `pinned=true`) → `changes`·`outbox(graph.changed)` |
| **검토 승인** | 묶음·대상 잠금 → 그사이 대상이 바뀌었으면 `superseded` → 나머지 적용 + `changes` → 남은 검토가 없으면 묶음 `done` |
| **되돌리기** | 새 묶음(kind = revert) → `changes`의 `before`로 적용(그사이 바뀐 대상은 검토로) → 원래 묶음 `reverted_by` |
| **대정리** | `reorg_open`: 묶음(open) → `reorg_add`: `change_ops`(pending)만 쌓음 → `reorg_submit`: 판정(전부 검토) → 승인한 것은 `approved` → 일꾼이 수백 건씩 나눠 적용 |
| **AI 초안 저장** | `idempotency` → 글 잠금(없으면 생성) → 판 INSERT → 임대 없으면 `head_revision_id` 갱신 → 참고 wiki(`post_wiki_refs`) 기록 → `changes` |
| **발행** | 관리 모드만. `status`, `published_at` → `outbox(post.published)` → 일꾼이 `blog.chunks`·임베딩 생성 |
