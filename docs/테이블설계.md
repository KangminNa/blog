# Cairn 테이블 설계

> 칼럼의 원본은 `db/migrations/`이고, 코드는 `apps/server/src/modules/<모듈>/<모듈>.tables.ts` · `<모듈>.schema.ts`(`pnpm db:rows`가 생성)로 표를 안다. 표의 주인은 `apps/server/modules.json`.
> 이 문서에는 코드만 봐서는 모를 뜻과 규칙만 둔다. "아직 안 씀"은 표는 있지만 쓰는 코드가 없다는 뜻이다.

## 0. 공통 규칙

| 항목 | 규칙 |
|---|---|
| DB | Postgres 17, 확장 `pg_bigm`(한국어 키워드), `vector`(pgvector), `pgcrypto` |
| 스키마 | **모듈 = 스키마.** `platform`(공통 기반), `account`(공간·사람·기기·로그인), `vault`(세션·그래프·변경 묶음), `blog`·`work`(글과 소재, blog 모듈 소유), `task`(에이전트·작업·결재), `mcp`(읽기 기록) |
| 모듈 사이 | **외래키를 두지 않는다.** 다른 모듈의 행을 가리키는 열(`space_id`, `device_id`, `blob_hash` 등)은 값만 갖고, 유효성은 주인 모듈의 코드가 지킨다. `pnpm db:check`가 막는다 |
| 기본키 | UUIDv7. 시간순이라 B-tree 끝에만 쌓여 쓰기에 유리하다. 앱에서 만들고 `platform.uuid_v7()`은 예비용이다. 로그 표는 `bigint` |
| 공간 | 사용자 데이터 표는 모두 `space_id`를 가진다. 지금은 공간 하나. 복합 인덱스는 `space_id`를 맨 앞에 둔다 |
| 삭제 | 사용자 데이터는 `deleted_at` + `purge_after`(휴지통) |
| 낙관적 잠금 | 사람이 고치는 행에 `version` |
| 행위자 | `actor_type`(`user`·`device`·`ai`·`system`) + `actor_id`. 사람이 읽는 표기는 화면에서 조립한다 |
| 열거형 | 자주 늘어날 종류는 목록 표(`node_kinds`, `edge_kinds`), 거의 안 바뀌는 상태값은 `text + CHECK` |
| 확장 열 | 주요 엔티티의 `meta`. 새 도구의 추가 정보, 복원한 md의 모르는 앞부분 키를 둔다 |
| 추가만 하는 표 | `session_revisions`, `wiki_revisions`, `post_revisions`, `task_events`, `skill_revisions`, `agent_revisions`, `task_runs`(비어 있는 `model`을 한 번 채우는 것만 된다). 트리거 `platform.forbid_update_delete()`가 UPDATE·DELETE를 막는다. 영구 삭제 일꾼만 `SET LOCAL cairn.allow_purge = 'on'`으로 지나간다 |

**문서를 저장하는 세 겹** (세션·wiki·글)

| 겹 | 열 | 역할 |
|---|---|---|
| 원문 | `body_md` | 원본. 내보내면 그대로 .md 파일이 된다 |
| 쪼갠 칸 | `sections`, `section_hashes` | 칸 단위 합치기, 화면 표시, 차이 비교 |
| 찾기용 복사본 | `head_*`와 검색 색인 | 목록·검색을 빠르게. 지금 판이 바뀔 때 같은 트랜잭션에서 고친다 |

판은 추가만 하고, 지금 보여줄 판은 부모 행의 `head_revision_id`와 `version`으로 가리킨다. 판 추가·포인터 갱신·일 임대·사람 우선 검사를 한 트랜잭션에 묶어야 하고 관계 규칙이 많아서 문서 DB가 아니라 Postgres를 쓴다.

## 1. 미리 해 둔 것

아직 쓰지 않는 열과 표가 있는 이유다.

| 나중에 생길 일 | 지금 해 둔 것 | 그때 할 일 |
|---|---|---|
| 팀 블로그, 공식 호스팅 | 모든 데이터에 `space_id`, `space_members.role` | 공간 추가, 행 수준 보안 켜기 |
| 새 점·연결 종류 | `node_kinds`, `edge_kinds` | 목록에 행 추가 (점은 상세 표도 하나) |
| 임베딩 모델 교체 | `platform.embedding_models`, 차원을 고정하지 않은 `vector` 열 + 모델별 부분 인덱스 | 모델 행 추가 → 다시 계산 → 인덱스 추가 |
| 세션 노트 칸 변경 | 판마다 `sections_schema` | 새 파서 추가, 옛 판은 그대로 |
| S3 등 파일 저장소 | `platform.blobs.storage_backend` | 백엔드 추가, 옮기기 작업 |
| 그래프 보기 여러 개 | `graph_views.settings`, `node_layout(view_id, node_id)` | 보기 행 추가. 설정이 늘어도 열을 늘리지 않는다 |
| 글 다국어 | `posts.lang` | 번역 글 연결 표 |
| 로그가 수억 건 | 시각 BRIN + 날짜 기준 삭제 (1인 블로그는 수백만 행도 충분) | 그때 월별 분할 |

## 2. `account` · `platform` · `mcp`

**account**

- `spaces`: 블로그 하나. 설치됐다 = 주인이 있다. 설치 코드는 서버 키에서 만들고 저장하지 않는다.
- `users`: `login`이 아이디다. `password_hash`는 `scrypt$N$r$p$salt$hash`이고 원문은 어디에도 두지 않는다.
- `login_links`: 로그인 플러그인으로 들어온 외부 계정과 주인의 연결. 여기에 연결된 계정으로만 주인 로그인이 된다.
- `space_members`: 공간마다 `owner` 한 명 (부분 유일 인덱스).
- `settings`: 값은 `blog.description`, `site.url`, `connect.hosted_apps`. `secrets`: 서버 키로 암호화한 값 (아직 안 씀).
- `devices`: 기기는 지우지 않고 `revoked_at`으로 끊는다 (다른 모듈이 id를 값으로 갖고 있다). 이름은 끊지 않은 기기 사이에서만 겹치지 않으면 된다. 권한 `sandbox`는 코드 러너 칸 기기만 갖고, 그 기기는 `run` · `sandbox`만 갖는다 (CHECK `devices_sandbox_only`). `is_primary_tidy`는 아직 안 씀.
- `oauth_codes`: 5분, 한 번만. 기기는 코드를 토큰으로 바꿀 때 `device_draft`로 만든다 (그만둔 승인이 남지 않게).
- `oauth_tokens`, `device_tokens`, `web_sessions`: 토큰은 해시만 저장한다.

**platform**

- `blobs`: 기본키가 내용의 sha256이다. `vault.attachments`, `blog.assets`, `blog.posts.cover_blob_hash`, `work.basket_items`, `vault.graph_snapshots`(그리고 `task.outputs`)가 값으로 가리키고, 도메인끼리는 서로를 모른다. 외래키가 없어 DB가 지켜 주지 않으므로, 가리키는 모듈이 `BlobStore.registerUse`로 "이 해시들 중 쓰는 것"을 등록하고 `BlobSweepJob`이 아무도 쓰지 않는 7일 지난 파일만 지운다. `created_at`은 마지막으로 저장한 때다 (다시 저장하면 새로 되어 지우기 기다림이 처음부터).
- `idempotency`: 같은 요청은 처음 결과를 돌려준다. `device_id`는 이름과 달리 호출한 쪽의 값이다: 기기, 주인, 작업 토큰이면 작업, 결재한 공개면 공간.
- `outbox`: 일꾼이 빌릴 때 `next_attempt_at`을 뒤로 미뤄 다른 일꾼이 잡지 않게 한다. 실패하면 `last_error`, 여러 번 실패하면 `failed_at`을 찍고 멈춘다 (지우지 않고 남겨 원인을 본다).
- `plugins`, `plugin_settings`: 설정은 DB에 둔다. `granted_uses`는 켤 때 주인이 허락한 확장 지점이다. 값은 `value`나 `secret_ciphertext` 중 하나만 있다.
- `notifications`, `push_subscriptions`: 7단계에 알림 일꾼이 outbox를 읽어 채운다. `embedding_models`: 의미 검색 때 쓴다. 모두 아직 안 씀.

**mcp**: `mcp_reads`는 기기별 읽기 기록이다 (아직 안 씀).

## 3. `vault`

### 그래프 = 대표 하나 + 선

| 점 | 대표 (열 하나) | 비어 있으면 |
|---|---|---|
| 세션 | `sessions.wiki_id` | 도착 구역 (정리 전) |
| wiki | `wikis.category_id` | 미분류 |
| 글 (blog) | `posts.main_wiki_id` (값). vault는 사본 `post_marks.main_wiki_id`로 안다 | 그래프에 나오지 않음 |

- 대표가 하나라는 규칙을 DB 구조로 지킨다. 옮기기·합치기는 대표 값 하나를 바꾸는 일이라, 카테고리를 바꿔도 바뀌는 행이 wiki 몇 개로 끝난다.
- "미분류"와 "도착 구역"은 행이 아니라 `NULL`이다. 지우거나 이름을 바꿀 수 없다.
- 대표 밖 연결은 `edges`의 선이다: `material`(세션 → 다른 wiki), `link`(wiki ↔ wiki), `replaces`(새 wiki → 결론이 뒤집힌 옛 wiki, [wiki 점수](wiki점수.md). 옛 wiki 하나에 하나만: `edges_replaced_once`), `similar`(계산값, 아직 안 씀). 글 → 다른 wiki는 `blog.post_wiki_refs`.
- 부모를 지워도 자식은 지워지지 않는다. 카테고리를 영구 삭제하려면 먼저 wiki를 옮겨야 하고(`RESTRICT`), wiki가 영구 삭제되면 세션은 도착 구역으로 간다(`SET NULL`). `CASCADE`는 같은 점의 일부(상세 행, 판, 그 점의 선, 검색 조각)에만 쓴다.

### 세션과 wiki

- `nodes`: 세션·카테고리·wiki를 한 표로 묶어 선이 외래키 하나로 걸리게 한다. 글은 점 표에 없다.
- `sessions`: 대화 하나가 `(space_id, device_id, tool, source_session_id)`다. `pinned_sections`는 사람이 고친 칸이고, 칸 이름 말고 `#title`(wiki 제목), `#wiki`(세션의 대표 wiki)도 들어간다. `tidy_requested_seq`는 정리를 요청한 마지막 판이다: `revision_count`보다 뒤처진 세션만 고르고, 실패한 세션은 새 판이 쌓여야 다시 고른다. 이 값을 적어도 세션 `version`은 오르지 않는다. `held_revision_id`는 편집 중이라 보류한 새 원본이다 (아직 안 씀).
- `session_revisions`: `kind`는 `origin`(AI 도구), `human`, `merge`. `redactions`는 지운 민감정보 표시다.
- `attachments`: 세션 판 ↔ 파일. 기본 비공개 (아직 안 씀).
- `categories`: `description`은 분류 기준이고 정리 스킬이 읽는다.
- `wiki_revisions`: `kind`는 `ai`, `human`, `merge`. 칸은 md 제목(`##`) 단위다. `base_revision_id`는 보고 고친 판, `change_set_id`는 나온 묶음이다.
- `wiki_aliases`: 합쳐져 없어진 wiki의 옛 주소. 글의 참고가 깨지지 않게 한다. `old_id`는 영구 삭제됐을 수 있어 외래키가 없다 (대정리, 아직 안 씀).
- `edges`: 방향 없는 종류는 `src < dst`로 정렬해 저장한다. 사람이 지운 연결은 행을 남겨(`deleted_at`, `deleted_by_type`) AI가 다시 만들지 못한다.
- `post_marks`: 글 자리 사본. vault는 blog를 읽지 않으므로, blog의 글 이벤트를 Handler가 받아 적고 그래프는 이것으로 글 점과 선을 그린다. 이벤트 순서가 바뀌어도 `post_version`이 큰 것만 반영한다. `status`는 `draft`·`published`뿐이라 링크만 공개는 `draft`로 적는다.
- `tidy_settings`: 행이 없으면 자동 정리 꺼짐. `project_rules`: 프로젝트별 기본 공개와 수집 여부 (아직 안 씀).
- `graph_views`: 방문자·주인의 기본 보기와 저장한 보기. `audience`마다 기본은 하나다. `settings`는 서버의 `GraphView`가 읽을 자리고, `node_layout`의 좌표는 보기마다 있다. 지금은 보관 파일만 고정한 점을 읽는다.
- `graph_snapshots`, `chunks`, `chunk_embeddings`: 스냅샷과 검색 조각. 다시 만들 수 있는 값이다 (아직 안 씀).
- `edit_leases`: 7장. `target_kind` CHECK에 옛 이름 `topic`이 남아 있다 (아직 안 씀).

### 변경 묶음

git처럼 다룬다: 결과 한 번 = 묶음(커밋) 하나, 승인함 = 검토를 기다리는 `change_ops`(PR), 대정리 = 작성 중인 묶음(브랜치), 되돌리기 = 새 묶음(revert). 관리 화면 편집도 묶음(`human`)으로 남기되 규칙은 거치지 않는다. 그래서 승인함·되돌리기·기록을 두 번 만들지 않는다.

- `change_sets`: `kind`는 `tidy`, `reorg`(대정리), `human`, `revert`, `system`. `status`의 `open`은 대정리 작성 중, `review`는 검토 대기다. `job_id`는 작업 id를 값으로 담고 유일해서 정리 결과의 중복 적용을 막는다: 러너가 `submit_changes`와 `submit_result` 사이에 죽어도 두 번째 제출은 첫 묶음을 돌려준다.
- `change_ops`: 요청한 일 하나. `op`는 서버의 `ChangeOp` 이름이다. `base_version`은 판정할 때 대상의 version이고, 승인할 때 어긋나면 `superseded`가 된다.
- `changes`: 실제로 바뀐 행의 `before`·`after`. `batch_id`는 묶음 id이고 되돌리기 단위다. `domain` CHECK에 옛 값 `app`이 남아 있다.
- `review_rules`: 주인이 고른 값만 둔다. 규칙의 뜻은 서버의 `ReviewPolicy`에 있고, 행이 없으면 기본값이다.

## 4. `blog`

- `posts`: `status`는 `draft`(임시) · `published`(공개) · `unlisted`(링크만). `title`은 지금 판의 찾기용 사본이다. `slug`는 한글을 허용하고 기본값은 제목에서 만든다. `main_wiki_id`는 vault의 값이라 외래키가 없다.
- `post_revisions`: 제목·본문이 바뀔 때만 판을 쌓는다. 주소·태그·정렬·공개 범위는 글에 둔다. `blocks`는 아직 안 씀.
- `post_wiki_refs`: 글이 대표 말고 참고한 wiki. 글의 출처는 이것으로만 남기고 세션은 wiki를 거쳐 안다.
- `assets`: 글 ↔ 파일. 사진의 공개 여부는 파일이 아니라 붙은 글로 정한다.
- `categories`: vault 카테고리와 따로이고 2단계, 글 하나에 카테고리 하나다 (아직 안 씀). `series`, `chunks`, `chunk_embeddings`, `edit_leases`도 아직 안 씀.
- `posts.stone_count`, `stone_log`: 공감. 코어는 쓰지 않는다 (플러그인을 만들 때 정리한다).

## 5. `work`

blog 모듈이 가진 스키마다.

- `baskets`: 공간마다 기본 상자 하나. 처음 담을 때 만든다.
- `basket_items`: 소재 하나. `kind`마다 필요한 칸을 CHECK가 정한다. `ref_id`는 세션·글의 값이라 외래키가 없다. 사진·파일은 표에 있지만 올리는 길이 없어 받지 않는다.

## 6. `task`

에이전트, 작업, 결재. 대기열이 둘이 되지 않게 정리 일도 `tasks`에 함께 둔다.

- 모듈 사이 외래키는 없다. `space_id`, `leased_by`, `decided_by`, `target_id`, `runners.device_id`는 값으로만 가리킨다. 모듈 안(`tasks.agent_id`, `approvals.task_id`, `agents.reports_to`, `goals.parent_id`, `tasks.goal_id`)은 외래키를 둔다.
- `agents.reports_to`: 보고 대상. 비어 있으면 주인이다. 자기 자신은 CHECK가, 순환과 깊이 4는 `Agent`가 막는다. 조직도를 바꿀 때는 공간의 에이전트를 모두 `id` 순서로 잠근다: 둘이 동시에 서로에게 보고하게 바꾸면 각자 본 조직도에는 순환이 없어서다.
- `goals`: 목표 나무 (맨 위가 회사 목표, 5단계까지). 지우지 않고 `done`·`dropped`로 닫는다. 부모는 만들 때 정하고 바꾸지 않아서, 목표 사슬은 잠그지 않고 재귀 CTE로 읽는다. 작업은 진행 중인 목표에만 잇는다 (`tasks.goal_id`).
- `agents.scopes`에는 `run`을 넣을 수 없다 (CHECK). 러너만 일을 빌린다. `browse`(서버 브라우저로 하는 작업)는 `read_all` · `write`와 함께 둘 수 없다 (CHECK `agents_browse_not_private`. `write`도 임시 글 · 소재를 연다). `code`(코드 러너 칸에서 하는 코드 작업)도 `read_all` · `write`와 함께 둘 수 없다 (CHECK `agents_code_not_private`). `approval_actions`는 결재를 올려 할 수 있는 동작이다. 쉬는 중인지는 저장하지 않고 계산한다.
- `tasks`: `target_*`는 다른 모듈의 대상이고 값으로만 둔다. `(space_id, request_id)`가 유일해서 같은 일 요청은 한 번만 들어온다.
- 위임 (`tasks.parent_id` · `depth` 0~3 · `rounds` 0~3 · `wait_reason`): 새 상태 없이 `waiting`에 무엇을 기다리는지(`approval`·`subtasks`)만 적고, `(status = 'waiting') = (wait_reason IS NOT NULL)`을 DB가 지킨다. 하위 작업의 `request_id`는 `delegate:<위 작업>:<AI의 id>`. 위 작업을 취소하면 아래 작업도 위 → 아래 순서로 잠가 함께 취소한다.
- `task_events`: 실행 기록. 보드, 오피스, 사용량이 같은 로그를 읽는다.
- `approvals`: 작업 하나에 기다리는 결재는 하나다 (부분 유일 인덱스). 한도 올리기처럼 작업이 없는 결재는 `task_id`가 비어 있다. 결재 화면은 `target_*`로 대상 모듈의 API에서 실제 내용을 읽고, AI가 쓴 요약을 보여 주지 않는다.
- `plan_usage`: 러너가 본 마지막 값 하나만 둔다. `window`가 예약어라 열 이름은 `period`다. `percent`는 초과 사용이면 100을 넘고, `resets_at`이 지나면 확인 전으로 본다.
- `ai_logins`: 공간과 도구(`claude`·`codex`)마다 한 줄. 자격은 서버 키로 암호화한다. Claude 토큰의 `expires_at`은 저장한 날부터 1년이고(CLI가 남은 기간을 알려 주지 않는다), Codex의 `auth.json`은 갱신 토큰이라 비운다.
- `heartbeats`: 에이전트마다 한 줄. `daily`(시간대 기준 하루 중 분 + ISO 요일)나 `hourly`(N시간마다), 시간대는 IANA 이름. 켜져 있으면 늘 다음 시각이 있다 (CHECK). 만든 작업의 `request_id`는 `heartbeat:<에이전트>:<시각>`이라 일꾼이 두 번 돌아도 작업은 하나다.
- `skills` + `skill_revisions`: 러너 스킬(`cairn-where: runner`)의 콘솔 판. 스킬 하나에 한 줄(`(space_id, name)` 유일)이 쓰는 판(`active_revision`, 비어 있으면 저장소 판)과 판 수를 든다. 판은 추가만 하고(`files`는 `SKILL.md`와 `references/*.md`의 경로 → 글, `hash`는 경로 순으로 이은 sha256, `based_on`은 고치기 시작한 판의 해시), 되돌리기는 `active_revision`만 옮긴다. 아직 줄이 없는 스킬의 첫 저장은 advisory 잠금(`task.skill:<공간>:<이름>`)으로 하나만 만든다. 저장소 판은 표에 없고 서버가 `skills/`에서 읽는다
- `agent_revisions`: 에이전트 설정 판. 주인이 정하는 칸(이름 · 역할 · 도구 · 권한 · 결재 동작 · 한도 · 보고 대상)이 바뀐 저장마다 그 판의 칸 전부를 `settings`에 남기고 `agents.settings_revision`을 올린다. 상태(멈춤 · 재개)와 같은 값 저장은 판을 만들지 않는다
- `task_runs`: 일을 빌려 줄 때마다 한 줄 (`(task_id, seq)` 유일. `attempts`는 고쳐 달라 · 깨우기에서 0으로 돌아가서 따로 센다). 어떤 에이전트 설정 판 · 스킬 판(출처 `repo`·`console`, 콘솔 판 번호, 해시) · 러너 빌드 · CLI 버전으로 돌았는지 남긴다. 지시문 글은 남기지 않는다 (비공개 내용이 쌓이지 않게, 비교는 판과 해시로 된다). `model`은 러너의 첫 `report_progress`가 비어 있을 때 한 번 채우고, 그 밖의 UPDATE · DELETE는 트리거(`task_runs_model_once`)가 막는다. `runner_id`는 account의 기기라 값으로만 둔다
- `outputs`: 결과물 (AI가 만든 파일을 러너가 올린 것). 어느 작업 · 실행(`run_id`)이 만들었는지, 이름(1~120자, 경로 · 제어 문자 없이, 점으로 시작하지 않게) · 종류 · 형식 · 크기(100MB까지), 파일은 `platform.blobs`를 값으로(`blob_hash`). `(run_id, name)`이 유일해서 같은 실행이 다시 보내도 한 줄이다. 주인이 지우면 휴지통(`deleted_at` · `purge_after` 30일, 둘은 함께 비거나 함께 찬다)이고, 기간이 지나면 일꾼(`OutputPurgeJob`)이 줄을 지운다. 파일은 아무도 쓰지 않을 때 platform의 `BlobSweepJob`이 지운다. 한도를 셀 때는 공간마다 advisory 잠금(`task.outputs:<공간>`)
- `runners`: 러너 기기마다 한 줄. 러너가 처음 닿을 때 생긴다. `last_seen_at`은 version을 올리지 않고, `accepting`을 끄면 `next_jobs`가 빈 목록을 돌려준다. 이름·종류는 account의 기기라 화면이 합친다.
- `schedules`: 7단계에 만든다. 지시, cron, 하루 한도, 다음 실행 시각을 둔다.

### 기능 패키지의 스키마

기능 패키지(객체설계 12장)는 자기 스키마 하나를 가진다. 마이그레이션은 `plugins/<이름>/migrations/`, 코어 표에 외래키를 걸지 않고 `space_id`는 값으로만 둔다.

- `browser_tabs` (`browser-tabs`): `reads`(탭 읽기 요청과 결과, `requested` · `done` · `failed`), `sites`(브라우저 에이전트의 사이트: 이름 · 시작 주소 · 허용 출처 1~10개, `version`). 자세히는 [브라우저](브라우저.md) 5장.
- `code_github` (`code-github`): `repos`(주인이 등록한 저장소: 이름 · 주소 · 기준 브랜치 · setup · checks, 지우지 않고 `archived_at`으로 보관. 보관하지 않은 같은 주소는 하나), `pulls`(러너가 연 PR: 작업 하나에 하나(`task_id` 유일, 값으로만), 번호 · 주소 · 브랜치 `cairn/<작업>` · `head_sha` · 검사 결과, `status` open · merged · closed, `version`은 head가 바뀔 때마다 올라 `code.pr.merge` 결재의 판이 된다). 자세히는 [코드 작업](코드작업.md) 5장.

## 7. 트랜잭션과 동시성

기준: **데이터를 잃지 않는 곳까지는 막지 않고, 사람의 의도끼리 부딪히는 곳에서는 멈추고 사람에게 묻는다.**

1. 세션 올리기는 항상 새 판을 추가한다. 동시에 들어와도 서로 덮지 않는다.
2. 같은 요청은 `request_id`로 한 번만 반영한다.
3. AI가 생각하는 동안 트랜잭션을 열어 두지 않는다. 일을 빌리고, 밖에서 처리하고, 짧은 트랜잭션으로 제출한다.
4. 제출할 때 다시 검사한다. 본 뒤에 대상이 바뀌었거나 사람이 손댄 것이면 적용하지 않고 검토로 보낸다.

| 동작 | 순서 (한 트랜잭션) |
|---|---|
| 세션 올리기 | (트랜잭션 전에 민감정보 제거) → `idempotency` 자리 잡기 → 대화 자리 잠금(`pg_advisory_xact_lock`, 세션이 없어도) → 세션 `FOR UPDATE` → 없으면 만들기 → 내용 해시가 이미 있으면 판 없이 끝(`unchanged`) → 판 추가, `head_*` 갱신 → `outbox(vault.session.saved)` → 결과 기록 |
| 일 빌리기 | `task.tasks`에서 `queued` + 맡을 수 있는 에이전트 `FOR UPDATE SKIP LOCKED` → `running` + 임대 15분 |
| 정리 결과 제출 | 묶음 자리 확인(`job_id`나 `idempotency`) → `change_sets` → 대상 잠금 → 변경마다 판정 → 바로 합칠 것은 적용 + `changes`, 검토는 `waiting`, 거부는 이유와 함께. 작업은 끝내지 않는다 (러너의 `submit_result`) |
| 콘솔 편집 | 묶음(`human`) → 대상 잠금 → `version` 비교 → 적용(사람 표시) → `changes` |
| 검토 승인 | 묶음 잠금 → 대상 잠금 → `base_version`이 다르면 `superseded` → 적용 + `changes` → 남은 검토가 없으면 묶음 `done` |
| 되돌리기 | 새 묶음(`revert`) → `changes`의 `before`로 적용 (대상이 그 묶음이 남긴 version과 다르면 409) → 원래 묶음 `reverted_by` |
| AI 초안 저장 | `idempotency` → 새 글이거나, 글 잠금 + `base_version` 비교 → 판 추가, wiki 연결 → 저장 |
| 공개 | 주인의 공개 범위 바꾸기, 또는 결재 뒤 `Post.publishApproved`. `status`·`published_at` → `outbox(blog.post.published)` |
| 복원 | 파일을 트랜잭션 밖에서 먼저 쓴다 → 잠금 → 빈 곳 확인 → 모듈마다 자기 스키마에 쓴다. 모듈을 한 트랜잭션에 묶는 유일한 곳이다 |

대상은 `종류:id` 글자 순서로 잠근다. 작업은 작업 → 결재 → 에이전트 순서로 잠근다.

부딪힐 때: 같은 대화를 두 번 올리면 하나씩 처리해 판을 둘 다 저장한다. 정리 결과와 사람 수정이 겹치면 늦은 쪽이 검토로 간다. 콘솔 두 곳에서 같은 글이나 wiki를 고치면 나중 저장을 409로 거절한다.

**세션 편집을 만들 때** (`edit_leases`, `held_revision_id`): 편집을 시작하면 잠금 대신 `edit_leases`에 행을 넣고 하트비트로 유지한다 (2분 끊기면 풀림). 그동안 그 세션의 정리 일과 AI의 연결 변경은 미룬다. 같은 세션의 새 원본은 막지 않고 저장하되 지금 판으로 올리지 않고 `held_revision_id`에 둔다. 편집 화면에는 새 원본이 들어왔다고 알리고, 아직 들어오는 중인 세션은 끝난 뒤 고치라고 권한다. 저장하면 시작한 판을 기준으로 칸 단위 3-way 합치기를 하고, 겹치면 편집 화면에서 고른다.

지원하지 않는 것: 세션 사이의 전역 순서 보장. 같은 세션 안의 판 순서만 서버가 받은 순서로 보장한다.

## 8. 인덱스

- 모든 외래키 열에 인덱스를 둔다. Postgres는 자동으로 만들지 않고, 없으면 삭제와 조인이 느려진다.
- 조회는 대부분 휴지통 제외라서 `WHERE deleted_at IS NULL` 부분 인덱스를 쓴다.
- 쓰기가 많은 판·로그 표는 인덱스를 최소로 둔다. 로그의 시각은 BRIN이다.
- 목록 화면은 필요한 열을 `INCLUDE`로 덮어 표를 읽지 않게 한다.
- 왜 있는지는 마이그레이션의 주석이 원본이다. 이름만으로 알기 어려운 것만 적는다.

| 인덱스 | 이유 |
|---|---|
| `tasks (space_id, priority DESC, id) WHERE status = 'queued'` | 일 빌리기. `SKIP LOCKED`와 함께 쓴다 |
| `task_events (at) WHERE tokens > 0` | 5시간·이번 달 사용량. 일을 빌릴 때마다 읽어서 토큰이 있는 기록만 훑는다 |
| `tasks (goal_id, id DESC) WHERE goal_id IS NOT NULL` | 목표별 작업과 목표의 작업 수 |
| `tasks (parent_id, id) WHERE parent_id IS NOT NULL` | 하위 작업과 남은 하위 작업 세기 |
| `heartbeats (next_run_at) WHERE enabled` | 일꾼이 1분마다 때가 된 하트비트를 찾는다 (`SKIP LOCKED`) |
| `runners UNIQUE (device_id)` | 러너가 닿을 때마다 한 줄을 고친다 |
| `sessions (space_id, last_revision_at DESC) WHERE wiki_id IS NULL` | 도착 구역. 정리 전 세션만 담긴 작은 인덱스 |
| `change_sets (actor_id, created_at)` | "이 기기가 이때부터 한 일" 되돌리기 |
| `change_sets UNIQUE (space_id) WHERE kind = 'reorg' AND status IN ('open','review')` | 대정리는 한 번에 하나 |
| `change_ops (target_id) WHERE status = 'waiting'` | 대상이 바뀌면 기다리던 검토를 찾는다 |
| `session_revisions UNIQUE (session_id, content_hash)` | 같은 내용 재전송 감지 |
| `chunk_embeddings HNSW ((embedding::vector(384))) WHERE model_id = 1` | 모델마다 부분 인덱스 하나. 질의도 같은 형변환과 조건을 써야 탄다 |

## 9. 보관과 정리

정해 둔 기간이다. **지우는 일꾼은 아직 없어서 지금은 아무것도 지워지지 않는다.**

| 대상 | 기간 |
|---|---|
| 휴지통 | 30일 (`purge_after`) |
| `platform.idempotency` | 30일 |
| `vault.changes` | 1년. 지나면 그 변경은 되돌릴 수 없다 |
| `vault.change_sets`, `change_ops` | 계속 (누가·왜·무엇을) |
| `mcp.mcp_reads` | 90일 |
| `task.tasks`, `task_events` | 계속 (실행 기록은 추가만, 한 달 사용량의 원본) |
| `task.skill_revisions`, `agent_revisions`, `task_runs` | 계속 (결과가 바뀐 까닭을 비교하는 원본) |
| `task.outputs` | 주인이 지울 때까지. 휴지통 30일 뒤 줄을 지우고, 파일은 아무도 쓰지 않으면 7일 뒤 |
| `platform.notifications` 읽은 것 | 90일 |
| `platform.blobs` | 어느 도메인에서도 쓰지 않고 7일 |
