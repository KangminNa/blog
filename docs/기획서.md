# Cairn 기획서

> 이름 Cairn · 라이선스 AGPL-3.0 · 1~6단계(첫 완성) 구현, 배포 전 · 최종 수정 2026-11-02
> 무엇을 왜 만드는지와 결정의 이유를 적는다. 구현의 원본은 코드이고, 설계는 [테이블 설계](테이블설계.md) · [객체 설계](객체설계.md) · [API 설계](API설계.md) · [보관 형식](보관형식.md)에 있다.

## 1. 무엇을 만드나

**내 서버 하나에서 도는 Personal AI OS. 흩어진 AI 세션을 모아 지식으로 키우고, 에이전트에게 작업을 맡겨 결재하고, 결과를 블로그로 내보내는 self-hosted 오픈소스.**

| 기둥 | 하는 일 |
|---|---|
| **모은다** | 여러 컴퓨터의 AI 세션을 스킬 한 번으로 내 서버(Postgres)에 모은다 |
| **자란다** | 러너가 세션을 wiki로 정리하고 연결을 만든다. 모든 변경은 변경 묶음으로 남고 서버의 검토 규칙을 거친다. 결과는 그래프로 보인다 |
| **맡긴다** | 콘솔에서 시킨 일을 에이전트가 하고, 위험한 동작은 주인이 결재한다 |
| **꺼낸다** | 소재로 에이전트가 초안을 쓰고 주인이 다듬어 공개한다. 글은 대표 wiki와 참고 wiki를 가리켜 그래프에 함께 보인다 |
| **다시 쓴다** | 다른 컴퓨터의 AI 도구가 MCP로 과거 세션과 wiki를 찾아 쓴다. 보관 형식으로 내보내 옵시디언이나 로컬 AI에서도 쓴다 |
| **지킨다** | 세션과 wiki는 기본 비공개이고, 올리기 전에 민감정보를 지우고, 공개 여부는 서버에서 거른 뒤에 개수·순위를 계산한다 |

## 2. 왜 만드나

AI 에이전트로 일하는 개발자는 매일 많은 세션을 만든다. 문제를 푼 과정, 설계 판단, 시행착오가 그대로 담겨 있지만 현실은 이렇다.

- 세션이 컴퓨터마다 흩어져 있다. 집에서 한 작업을 회사 컴퓨터에서 찾을 수 없다.
- 세션은 쌓이기만 하고 정리되지 않는다. 프로젝트를 넘나드는 주제가 이어지지 않는다.
- 좋은 작업 과정이 있어도 글로 옮기려면 처음부터 다시 정리해야 한다.
- 일을 맡겨도 내 컴퓨터가 꺼지면 멈춘다.

| 서비스 | 하는 것 | Cairn과 다른 점 |
|---|---|---|
| WordPress.com + MCP, Elementor Angie | AI 에이전트가 글과 사이트를 편집 | 입력이 "내가 쓰라고 시킨 글"이다. Cairn은 AI 작업 세션 자체가 원재료다 |
| Notion, Beehiiv 등 AI 블로깅 | AI 글쓰기 보조 | 글쓰기 보조는 목표가 아니다 |
| Obsidian | 로컬 마크다운 지식 그래프 | 세션 수집, 관리 AI, 공개 블로그가 없다. Cairn의 보관 파일은 옵시디언에서 열린다 |
| LLM Wiki (Karpathy 패턴, nashsu/llm_wiki) | 원천 자료를 LLM이 위키로 정리 | 가운데 층(raw → wiki → 산출물)을 공유하는 선행 사례. 원재료가 여러 컴퓨터의 AI 세션이고, 결과가 공개 그래프와 블로그이고, 앱이 아니라 내 서버다 |

세션 쪽만 보면 "AI 작업 세션을 위한 LLM Wiki, 그리고 그것을 공개하는 블로그"다.

## 3. 대상과 목표

**대상**: Docker로 서버를 직접 띄울 줄 아는 개발자. Claude Code나 Codex를 매일 쓰고, 여러 컴퓨터를 오가고, 작업 과정을 남기고 싶지만 글쓰기가 부담스럽고, 데이터를 내 서버에 두고 싶은 사람.

**첫 완성이 증명할 것**

1. 여러 컴퓨터의 AI 세션이 스킬 한 번으로 빠짐없이 한 서버에 모인다.
2. 모인 세션이 그래프로 정리되고, 사람이 고친 것이 AI에 덮이지 않는다.
3. 다른 컴퓨터의 AI 도구가 MCP로 과거 세션을 찾아 작업에 쓴다.
4. 그 자료로 읽기 편한 블로그 글을 쓰고 공개한다.
5. 웹에서 시킨 작업을 컴퓨터가 꺼져 있어도 에이전트가 하고, 위험한 동작은 결재를 거쳐야만 실행된다.

| 성공 기준 | 값 |
|---|---|
| 설치 | `docker compose up`부터 첫 세션 도착까지 15분 이내 |
| 올리기 | `cairn-save` 실행부터 그래프에 점이 생길 때까지 3초 이내 |
| 데이터 보존 | 기기 3대가 같은 세션을 동시에 올리는 테스트에서 유실 0건 |
| 사람 우선 | 사람이 고친 칸·연결이 정리 스킬에 의해 바뀌는 경우 0건 |

## 4. 원칙

바꾸지 않는 원칙 일곱 개는 [AGENTS.md](../AGENTS.md)에 있다. 그 아래에서 제품을 고르는 기준은 이렇다.

1. **데이터는 사용자 소유다.** 보관 형식으로 언제든 전부 내보내고 다시 복원한다.
2. **AI는 가져와서 쓴다.** 서버는 시킬 일만 정하고, 어떤 AI가 할지는 사용자가 고른다.
3. **최소 요구사항은 서버 하나다.** 러너를 켜지 않으면 블로그와 세션 허브로만 돈다. 의미 검색 같은 것은 켜면 좋아지는 옵션이다.
4. **raw와 wiki를 섞지 않는다.** 세션은 일을 한 AI가 남긴 근거이고, wiki는 다른 AI나 사람이 정리한 해석이다. AI는 세션을 고치지 않는다.
5. **규칙은 서버가 강제한다.** 사람 우선, 검토 전환, 형식 검사는 서버가 한다. 스킬은 제안할 뿐이고 건너뛰어도 벽이 남는다.
6. **지우는 길은 콘솔뿐이다.** MCP는 올리기·읽기·정리·초안까지 한다. AI가 지울 수 있는 것은 AI가 만든 선뿐이다.

## 5. 구성

```
[내 컴퓨터들]                                  [내 서버 · Docker Compose]
 Claude Code · Codex                          ┌───────────────────────────────────┐
  ├ cairn-save   (넣기) ── MCP ──────────────▶│ server : REST · MCP · 인증 · SSE  │
  └ cairn-recall (찾기) ── MCP ──────────────▶│ worker : 이벤트 · 플러그인 반복 작업 │
 Claude 앱 · ChatGPT    ── MCP ──────────────▶│ web    : 블로그 · 콘솔            │
 러너 (선택)            ── MCP ──────────────▶│ db     : Postgres                 │
 브라우저 ── HTTPS (사용자의 리버스 프록시) ──▶│ 볼륨   : 사진 (내용 해시 이름)    │
                                              │ runner : AI 작업 실행 (선택)      │
                                              └───────────────────────────────────┘
```

| 스킬 | 어디서 | 하는 일 |
|---|---|---|
| `cairn-save` | 사람의 AI 도구 | 대화를 세션 노트로 쓰고, 다른 맥락의 검토와 사용자 확인을 거쳐 저장한다 |
| `cairn-recall` | 사람의 AI 도구 | wiki와 세션에서 찾아 출처와 함께 답한다. 읽기만 한다 |
| `cairn-tidy` | 러너 | 세션 하나를 wiki로 정리하고 대표 wiki와 연결을 정한다 (`tidy_session`) |
| `cairn-write` | 러너 | 소재와 세션으로 초안을 저장하고 공개 결재를 올린다 (`draft_post`) |

스킬의 내용은 `skills/`가 원본이다. MCP 도구는 [API 설계](API설계.md) 4장.

## 6. 기능 범위

### 6.1 첫 완성 (1~6단계)

| 영역 | 기능 |
|---|---|
| 설치 | Docker Compose 한 벌, 설치 마법사 5단계 (설치 코드 → 관리자 계정 → 사이트 정보 → 플러그인 → 첫 기기) |
| 인증 | 콘솔은 주인 아이디·비밀번호, 외부 로그인은 플러그인. MCP는 OAuth(주인이 승인)와 예비 기기 토큰. 새 기기는 올리기 + 공개 읽기로 시작하고 나머지 권한은 콘솔에서 켠다 |
| 연결 | Claude Code · Codex는 `cairn connect`, Claude 앱 · ChatGPT는 콘솔의 안내와 스킬 zip |
| 세션 수집 | 세션 노트(제목 · 한 일 · 결정 · 막힌 점 · 인용 · 기타), 판 쌓기, 중복 방지, 민감정보 두 번 제거 |
| 작업 | 에이전트, 작업 보드, 결재, 실행 기록, 토큰 한도, 내 컴퓨터 러너와 서버 러너(Claude · Codex), 웹 AI 로그인, 러너 메뉴, 오피스 플러그인 |
| 정리 | 러너가 세션을 wiki로 정리, 변경 묶음과 검토 규칙, 승인함, 되돌리기. 자동 정리는 기본 꺼짐 |
| 지식 | wiki 판 쌓기, 카테고리, 그래프(방문자·주인), 세션·wiki 키워드 검색(pg_bigm) |
| 블로그 | 글 목록, 글 페이지, RSS, 쓰는 화면이 곧 보이는 편집기(저장은 md), 공개 범위, 휴지통, 사진, 소재, 글과 wiki 연결 |
| 보관 | 콘솔의 zip 내보내기, GitHub 동기화 플러그인, 빈 Cairn으로 복원 |
| 플러그인 | `comments-giscus` · `sync-github` · `login-github` · `office` |

### 6.2 다음 단계 (7·8단계)

**7 스케줄·알림**: 스케줄(하루 한도 포함)과 알림.

| 알림 등급 | 이벤트 | 방식 |
|---|---|---|
| 즉시 | 새 기기 연결, 처음 보는 곳에서의 접근, 민감정보 의심, 원본 충돌, 백업 실패 | 바로 |
| 묶음 | 세션 들어옴, 정리 결과, 승인할 제안, 정리 대기 쌓임 | 1시간이나 하루 한 번 모아서 |
| 기록만 | 자동 반영된 정리, 읽기 기록 | 알림 센터에만 |

경로는 콘솔의 알림 센터(실시간), AI 도구 안(MCP 응답에 실어서), 브라우저 푸시(외부 서비스 없이 서버 키로), 이메일(SMTP, 하루 요약 위주)이다. 같은 종류는 묶어 보내고, 조용한 시간과 종류별 경로를 설정에서 고른다.

**8 연동·SNS**: Slack, Gmail, Telegram, X, Threads, 이미지 생성. 전송은 결재를 거친다.

### 6.3 뒤로 미룬 것

| 미룬 것 | 그때의 설계 |
|---|---|
| 대정리 | 바로 적용하지 않고 정리 계획을 만든다. 전후 비교를 보고 골라 승인하면 일꾼이 나눠 적용하고, 통째로 되돌린다. 비공개 → 공개 전환은 한 번 더 확인. wiki를 합치면 옛 id 연결표를 남긴다 |
| 세션 고치기 | 콘솔에서 세션 고치기(사람 판), 공개 설정, 지우기, 칸 단위 자동 병합, 편집 임대 ([테이블 설계](테이블설계.md) 7장). 지금 콘솔의 세션은 읽기만 하고, 새 세션은 모두 비공개다 |
| 의미 검색 | 키워드 + pgvector를 합쳐 순위(RRF)를 내고 최근성·그래프 거리를 더한다. 서버에 내장한 소형 다국어 임베딩(CPU)으로 계산하고 Ollama·API로 바꿀 수 있다. 세션은 칸 단위로 쪼갠다 |
| 그래프 전송 | 뼈대만 보내고 내용은 누를 때. 좌표는 일꾼이 계산하고 스냅샷은 최대 10초에 한 번. 공개 스냅샷은 그대로 캐시, 콘솔은 SSE로 변경분, 브라우저는 IndexedDB에 둔다. 이미 받은 그래프 안의 찾기는 서버에 묻지 않는다 |
| 러너 | 콘솔 대화창, 웹뷰 앱, Claude · Codex 밖의 구독 CLI (Gemini · Copilot 등은 acpx로, 2026-11-07) |
| 블로그 | 카테고리, 시리즈, 글 목차, 방문자 검색, 갤러리·영상·링크 카드 블록, 세션 재료 패널, 문체 가이드 |
| MCP 도구 | 세션 사진 첨부(`attach_file`), AI 도구에서 소재 담기(`basket_add`), 참고 글 찾기(`blog_search`), 사진(`blog_upload_asset`, `blog_copy_asset`), 문체(`blog_style`) |
| wiki 점검 | 끊어진 링크, 고립된 문서, 중복 주제, 오래된 내용을 찾아 고치는 주기 작업 |
| md 가져오기 | 옵시디언에서 고친 파일을 칸 단위로 합쳐 사람 판으로 넣는다. 지금은 빈 Cairn에 복원만 한다 |
| 그 밖 | 매일 블로그 작업본 이메일, 메신저 웹훅, S3 저장소, PDF·HTML 첨부, 공감(플러그인 후보) |

### 6.4 만들지 않는 것

음성, 격리 브라우저, 스킬 마켓, 여러 회사 운영, 구독 프록시, 웹 터미널, 코어 안의 댓글(플러그인으로), 세션 자동 올리기, 여러 관리자, 실시간 공동 편집, 콘솔의 오프라인 편집.

## 7. 사용자 흐름

**처음 설치**: 서버에서 `docker compose up` → 로그의 설치 코드 확인 → `/install`에서 설치 코드, 관리자 계정, 사이트 정보, 플러그인, 첫 기기. 순서는 [README](../README.md).

**기기 연결**: 노트북에서 `pnpm cairn connect https://내블로그 [--tool codex]` → 스킬·검토자 넣기, MCP 등록 → 브라우저에서 로그인하고 기기 이름을 정해 승인 → 연결 확인.

**넣기**: 작업 뒤 "이 세션 저장해" → 스킬이 노트를 쓴다 → 검사와 검토 → 미리보기를 보고 확인 → 서버 저장.

**다시 쓰기**: 다른 컴퓨터에서 막혔을 때 "전에 어떻게 했지?" → `cairn-recall`이 찾아 출처와 함께 답한다.

**정리**: 자동 정리를 켜면 세션 저장 뒤에 일이 생기고, 끄면 세션 메뉴의 버튼으로 쌓인 세션을 20개씩 요청한다 → 러너가 일을 빌려 `cairn-tidy`로 처리 → 변경 묶음 제출 → 바로 합치거나 승인함으로.

**맡기기**: 홈이나 작업 메뉴에서 지시 → 러너가 빌려 실행 → 위험한 동작은 결재로 올라온다 → 주인이 승인 → 서버가 실행하고 작업을 끝낸다.

**글쓰기**: 소재에 세션·글·링크·메모를 담는다 → "이 소재로 초안 쓰기" → 에이전트가 초안을 저장하고 공개 결재를 올린다 → 콘솔 편집기에서 다듬고 승인. 직접 쓸 때는 글 메뉴의 편집기에서 바로 쓴다.

**백업과 복원**: `sync-github`가 5분마다 저장소에 맞춘다. 서버가 고장 나면 새 Cairn에서 복원 미리 보기를 보고 복원한다. 기기는 다시 연결한다.

## 9. 그래프 형태

그래프는 **나무 + 선**이다. 모든 점은 주소가 딱 하나라서 그 자리에 놓이고, 주소 말고 다른 연결은 선으로 따로 보인다.

| 점 | 누가 만드나 | 주소 |
|---|---|---|
| 카테고리 | 사람이 만든다. AI가 만들면 검토를 거친다 | 지도 위의 구역 |
| wiki | AI가 여러 세션을 모아 쓴 정리 문서. 사람도 쓰고 고친다 | 카테고리 하나. 없으면 미분류 |
| 세션 | AI 도구가 올린 원본 | 대표 wiki 하나. 정리 전이면 도착 구역 |
| 글 | 사람이 공개 | 대표 wiki 하나의 꼭대기. 대표 wiki가 없는 글은 나오지 않는다 |

| 선 | 뜻 |
|---|---|
| 재료 | 세션 → 대표가 아닌 다른 wiki. 세션 하나가 여러 wiki의 재료가 될 수 있다 |
| 참고 | 글 → 대표가 아닌 다른 wiki |
| 링크 | wiki ↔ wiki |

**공개 범위**: 카테고리 이름은 공개다. wiki와 세션은 각자 공개·비공개가 있고, 글은 임시(나만) · 공개(목록에 보임) · 링크만(주소로만, 목록·RSS 제외) 중 하나다. 방문자는 카테고리, 공개 wiki·세션, 공개 글만 본다. 공개 글이 가리키는 비공개 wiki만 이름·날짜 없는 자리로 남고, 그 밖의 비공개는 흔적 없이 빠진다.

**모양**: 옵시디언 그래프 뷰처럼 점과 선이 힘으로 자리를 잡는 평면 그래프다. Canvas로 그리고 계속 움직인다. 모든 연결은 흐린 선으로 보이고, 점을 고르면 그 점과 이웃만 남는다. 끌면 이웃이 따라온다. 캐릭터나 게임 요소는 두지 않는다.

**바꿀 수 있는 것**: 찾기, 점 종류별 끄기, 노드 크기, 선 굵기, 밀어내는 힘, 연결 거리, 성장 재생. 뒤로 미룬 것: 구역 기준(프로젝트·AI 도구·기간), 선 보기 방식, 점 위치 고정 화면.

저장 방식은 [테이블 설계](테이블설계.md) 3장이다.
