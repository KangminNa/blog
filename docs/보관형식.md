# Cairn 보관 형식 (v1)

> 2026-10-10. Cairn의 내용을 파일 묶음으로 내보내고 다시 들여오는 형식.
> GitHub 동기화 플러그인(`sync-github`), md 내보내기(zip), 복원이 모두 이 형식을 쓴다.
> 형식을 바꾸면 `ARCHIVE_FORMAT`(apps/server/src/modules/platform/archive/archive.query.ts)을 올리고, 복원과 이 문서를 함께 고친다.

## 원칙

- **원본은 DB다.** 이 형식은 이력·백업·옮기기용 사본이다.
- **내용은 전부, 운영 데이터는 빼고.** 다시 계산되는 값(검색 조각, 임베딩, 그래프 스냅샷)도 빼고 복원할 때 다시 만든다.
- **비밀값은 절대 넣지 않는다.** 기기, 토큰, 로그인, 비밀 설정.
- **vault는 비공개 저장소에만.** 공개 저장소로 보낼 때는 `vault/`를 빼고, 공개 저장소에 `vault/`가 이미 있으면 동기화를 멈춘다 (git 이력에 남기 때문).
- **id를 지킨다.** 모든 항목은 앞부분(frontmatter)에 `cairn_id`를 가져서, 경로가 바뀌어도 같은 항목으로 되살아난다.

## 폴더

```
cairn.json                                  형식 버전 {"format": 1, "generator": "cairn"}
blog/posts/<연도>/<주소>.md                  글
blog/_meta/categories.yml · series.yml       블로그 카테고리 · 시리즈
vault/categories.yml                        그래프 카테고리 (이름, 색, 순서, 분류 기준)
vault/wikis/<주소>.md                        wiki
vault/sessions/<프로젝트>/<날짜>-<주소>.md     세션 (raw)
vault/graph.json                            선(재료·링크·비슷함)과 출처·고정·사람이 지운 흔적, 고정한 점 위치
assets/<sha256>.<확장자>                     사진·첨부. 같은 내용은 한 번만
```

보관 형식이 관리하는 경로는 위의 것뿐이다. 저장소의 다른 파일(README 등)은 건드리지 않는다.

## md 파일

기획서 7.5의 옵시디언 호환 형식을 따른다. 앞부분 키는 평평하게, Cairn 전용 키는 `cairn_` 접두어.

| 종류 | 앞부분 (필수) | 앞부분 (있으면) | 본문 |
|---|---|---|---|
| 세션 | `cairn_format`, `cairn_type: session`, `cairn_id`, `title`, `visibility`, `tool`, `started` | `cairn_wiki`(대표 wiki id), `project`, `device`(이름), `tags` | 고정 소제목 `## 한 일` `## 결정` `## 막힌 점` `## 인용` `## 기타`, 사진은 `![](../../assets/<해시>.png)` |
| wiki | `cairn_format`, `cairn_type: wiki`, `cairn_id`, `title`, `visibility` | `cairn_category`(id, 비어 있으면 미분류) | 본문 md, 다른 wiki는 `[[제목]]` |
| 글 | `cairn_format`, `cairn_type: post`, `cairn_id`, `title`, `slug`, `status`, `published` | `cairn_main_wiki`, `cairn_ref_wikis`, `category`, `series`, `tags`, `cover`, `align` | 본문 md (블로그 확장 문법 포함) |

모르는 앞부분 키는 버리지 않는다. 복원할 때 `meta`에 보관했다가 다음 내보내기 때 그대로 돌려준다.

## 이력

- 판 하나하나는 파일로 남기지 않는다. 내보낼 때의 **현재 판**만 파일이 되고, 지난 판은 git 커밋 이력으로 본다.
- 커밋 단위: 글은 발행·수정마다 한 커밋, vault는 5분마다 바뀐 것을 모아 한 커밋.

## 복원

- **빈 Cairn에만** 복원한다 (데이터가 있는 곳에 섞어 넣기는 다음).
- 순서: 형식 검사 → 무엇이 몇 개 들어오는지 미리 보여줌 → 확인 → 나눠서 들여옴.
- 세션·wiki·글은 현재 판을 첫 판으로 되살린다. 검색 조각·임베딩·스냅샷은 일꾼이 다시 만든다.
- 기기는 다시 연결해야 한다.

## 단계별로 채워지는 것

| 단계 | 내보내기·복원에 들어가는 것 |
|---|---|
| 지금 | `cairn.json` |
| M1 | 세션, 사진 |
| M2·M3 | 카테고리, wiki, 선, 고정한 점 위치 |
| M4 | 글, 블로그 카테고리·시리즈 |

각 단계는 "예시 데이터 → 내보내기 → 빈 DB에 복원 → 내용 비교" 테스트를 함께 만든다.
