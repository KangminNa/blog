## 1. 목적

**어디서든 나를 돕는 "서브 나".** 내 Claude Code 세션과 웹에서 하는 일을 내 서버 한곳에 모은다. 일을 맡기면 서버의 AI 팀이 **AI끼리 이야기하며 목표까지** 가고, 나는 **목적을 말하고 결재만** 한다. 결과는 HTML로 남기고, 공개할 것은 블로그로 내보낸다.

나에게 오는 것은 이것뿐이다. 결재는 콘솔과 폰에서만 한다 (기기 · AI는 결재하지 못한다).

| 나에게 오는 것 | 예 |
|---|---|
| 공개 · 발행 | 블로그 글, 페이지의 새 판, 매거진 호 |
| 머지 · 배포 | maintainer의 PR, 코드 작업의 PR |
| 브라우저의 마지막 클릭 | 제출 · 결제 · 게시 (기록을 보고 내가 누른다) |
| 목표 완료 확인 | AI의 "다 됐다"는 주장이다 |
| 방향이 갈린 질문 | 양쪽 요약 + 버튼 하나 |
| 설정 · 자동화 적용 카드 | 대화로 바꾼 것은 카드로 오고, 적용을 눌러야 바뀐다 |
| 한도에 닿음 | 계속할지 |

       │ 맡기기 · 소식                 │ 모으기 · 맡기기            │ 브라우저 일
┌ 내 서버 (Cairn) ─▼──────────────────────────────▼─────────────────────────┴──────┐
│ 모이는 곳: 세션 · 위키 · 결과물 · 대화 · 결재                                        │

| 어디 | 새로 / 넓힘 | 하는 일 |
|---|---|---|
| Cairn 서버 (`apps/server` · `apps/web`) | 넓힘 | 대화 중심 화면, 대화의 참여자 · 목표 · 상태판 · 한도, 소식함, 받을 것과 검사, 자라는 페이지, 자동화, 블로그 메뉴 · 매거진, 정리 |
| 브라우저 확장 (`apps/extension`, 2단계) | 새로 | 웹 AI 대화 자동 모으기, 페이지 보내기, "이 페이지로 맡기기", 결재 배지 |

만들지 않는 것: AI 자체(Claude Code · Codex CLI를 구독으로 쓴다. 서버 본체에는 AI가 없다), AI 브라우저(Chrome을 전용 프로필로 띄운다).

## 3. 대화가 메인이다

- 콘솔의 첫 화면은 대화다. 메뉴(결과물 · 블로그 · 어시스턴트 · 자동화 · 러너 · 지식)는 대화가 만든 것을 보고 다듬는 곳이다.
- **대화 하나 = 프로젝트 + 목표 + 받을 것 + 참여자**(나 · 내 컴퓨터 세션 · 에이전트들). 대화에서 생긴 작업 · 결과물 · 브랜치 · 결재가 대화에 매달린다.
- 내 컴퓨터 세션은 MCP로 대화에 들어와 나 대신 에이전트와 이야기한다. 세션의 말은 "기기의 말"로 남는다: 지시 기준(`read_url`이 열 수 있는 사이트)을 넓히지 않고, 결재하지 못한다.
- 대화로 설정 · 자동화 · 공개를 바꾸면 **카드**가 생긴다. 내가 적용(결재)해야 바뀐다.
- 목표 실행(회차 루프)은 대화의 "목표까지 이어 돌기"로 합친다.

## 4. AI끼리 일하는 규칙

| 역할 | 하는 일 |
|---|---|
| 대표 | 받을 것에서 거꾸로 계획하고 나눠 맡긴다. 갈린 의견을 정한다 |
| 실행 담당 | 만든다 (리서처 · 분석가 · 제작자 · 브라우저 담당 · 코드 담당) |
| 검토 담당 | 기준표로 점수를 매기고 반론한다. 만든 쪽과 **다른 도구**(Claude ↔ Codex) |
| 판정 | 받을 것의 검사. 하네스와 서버(믿는 코드)가 한다. AI의 "다 됐다"는 주장이다 |

- **상태판:** 대화마다 목표 · 받을 것 · 기준표 · 정한 것(다시 따지지 않음) · 열린 질문 · 시도 기록. 메시지에는 종류(제안 · 반론 · 결정 · 질문 · 결과)를 단다.
- **질문 사다리:** 팀(대표) → 내 컴퓨터 세션 → 서버의 기억(결정 기록 · 위키 · 프로젝트 방향, 내 컴퓨터가 꺼져 있을 때) → 나(방향이 바뀌는 질문만, 버튼으로).
- **멈춤:** 대화마다 한도(기본 회차 10 · 2시간 · 토큰). 점수가 두 번 연속 오르지 않으면 최선안을 내고 멈춘다. 같은 쟁점에서 두 번 맞서면 대표가 정하고, 방향 문제면 나에게 올린다.
- **경쟁 두 안:** 공개 글 · 매거진처럼 중요한 결과물에서만 켠다 (토큰이 두 배).
- **퍼지지 않게:** AI의 말은 서로에게 자료다. 지시는 내가 확인한 목표와 받을 것뿐이다. 위험한 동작은 AI끼리 합의해도 결재다. 러너의 벽은 그대로다.

## 5. 받을 것

목표를 시작할 때 **끝에 받을 것 하나**를 고른다. 기본은 세션이 요청을 보고 고르고, 애매할 때만 나에게 묻는다. 세부 모양(보고서 · 표 · 발표 · 지도)과 가는 길(웹 검색 · 브라우저 · 팀원)은 AI가 정한다.

| 받을 것 | 어디까지 가나 | 완료 검사 |
|---|---|---|
| HTML | 만들어서 결과물 보관함까지 | `index.html`, 고른 모양의 필수 구성, 근거의 출처 링크 |
| 블로그 | 메뉴에 올리고 공개 결재까지 | 메뉴 지정, 편집 방침, 쓴 재료 표시 |
| 브라우저 동작 | 마지막 클릭 직전까지 | 허용 출처 안에서만 움직였는지, 마지막 동작 앞에서 멈췄는지. 결과는 기록 + 남은 클릭 |
| 코드 (저장소 프로젝트만) | `cairn/<작업>` 브랜치 | `pnpm check` · 테스트 통과 |
| (안 고름) 대화 답 | 말풍선 | 없음 |

받을 것의 검사 규칙은 판으로 쌓고, 진행 중인 목표는 시작할 때의 판으로 고정한다. 지금 페이지 주문(`payload.page`)의 "`index.html`이 없으면 실패"가 첫 사례다.

## 6. 러너와 하네스

| 러너 | 셸 | AI가 도는 동안 바깥 | 맡는 일 |
|---|---|---|---|
| 일반 러너 (서버, 프로세스 하나에 동시 N, 기본 3) | 없음 | 일반 인터넷 | 조사 · 글 · 대화 · 검토 |
| 샌드박스 러너 (서버, 칸 하나에 일 하나) | 있음 (AI는 `agent` 사용자) | 모델 API + 서버만 | 코드 · 파일 만들기 · 페이지 고치기 |
| maintainer (샌드박스 한 종류) | 있음 | 따로 망 · 따로 허용 목록 | Cairn 자신 · AI CLI · 스킬 · 확장의 사이트별 읽기 최신화. PR까지 |
| 내 Mac 러너 (선택) | 없음 | 인터넷 + 내 네트워크 | 묶인 에이전트의 일만. AI 브라우저 조작 (7장) |

- 화면 이름 "칸"은 "샌드박스"로 바꾼다.
- 맞추기: 일의 종류 → 필요한 라벨 → 에이전트의 묶기 → 러너의 라벨. 맞는 러너가 없으면 기다린다. 위험한 라벨(`sandbox` · `cairn-repo`)은 서버만 준다. 러너는 어시스턴트를 모르고, 설정(모델 · 지시 · 스킬 · 기억)은 서버가 일과 함께 보낸다.
- 하네스: ① 빌리기 → ② 준비(clone · 의존성 · 재료 · 지시 파일 · 스킬 · MCP 설정, AI 없음) → ③ AI → ④ 끝(검사 · push · 결과물 · 기억 메모 · 제출, AI 없음) → ⑤ 치우기.
- 지키는 규칙: 셸과 자유로운 인터넷을 한 러너에 두지 않는다. 셸과 비공개도. 비밀(GitHub 토큰 · AI 로그인)은 하네스 메모리에만. 내 컴퓨터에는 쓰지 않는다: 결과는 서버에 두고 내 세션이 가져간다.

## 7. 웹: 두 개의 브라우저

| | 내 브라우저 (매일 쓰는 것) | AI 브라우저 (내 Mac, 전용 프로필) |
|---|---|---|
| 하는 일 | 보고 모으기만 | AI가 조작 |
| 어떻게 | Cairn 브라우저 확장 (기기 하나로 연결) | Mac 러너가 CDP + Playwright MCP로 |
| 모으는 것 | 정한 사이트(ChatGPT · Claude · Gemini 웹 대화 기본)의 대화 → 세션, 내가 보낸 페이지 · 하이라이트 | 작업 기록 · 화면 |
| 로그인 | 내 모든 계정 | 일에 필요한 사이트만 |

- 내 브라우저에서 AI는 클릭하지 않는다. 숨은 지시 하나로 모든 계정이 위험해지기 때문이다. 방문 기록 전체는 모으지 않는다.
- 웹 대화는 Claude Code 세션과 같은 세션 형식으로 저장하고, 민감정보 지우기를 거친다.
- 사이트마다 읽는 부분을 작게 따로 둔다. 화면 구조가 바뀌어 깨지면 maintainer가 매일 점검해 고치는 PR을 올린다.
- 서버 브라우저(neko)는 늘 켜져 있고, 화면은 콘솔에서 HTTPS로 보고 누른다 (2026-11-14 구현, [브라우저](브라우저.md) 3장). 포트를 따로 열지 않는다.
- Mac 러너의 브라우저 조작 조건: 전용 프로필(`--user-data-dir`) · 러너 설정의 스위치 · Mac에 묶인 에이전트의 일만(묶이지 않은 브라우저 일은 서버 브라우저로) · 사이트의 허용 출처 · 브라우저 일에는 나눈 폴더를 주지 않음 · 마지막 클릭은 결재 뒤 내가. 창이 내 화면에 보인다.
- 대표와 브라우저 담당은 나눈다. 대표는 나눈 폴더를 볼 수 있어, 같은 AI가 브라우저까지 만지면 파일 내용을 웹으로 내보낼 수 있다. 브라우저 담당의 보고는 대표에게 자료로만 간다.
- 대표를 Mac에 묶으면 Mac이 꺼졌을 때 멈춘다 (다른 러너가 대신하지 않는다). 그때는 바로 소식으로 알린다.

## 8. 코드

- 프로젝트 = 저장소 + 기준 브랜치 + 그 프로젝트의 팀. 세션의 git remote로 프로젝트를 찾는다.
- 맡길 때 push 안 한 변경은 스킬이 `wip/…` 브랜치로 올리고 그 커밋을 기준으로 넘긴다.
- 어시스턴트는 `cairn/<작업>` 브랜치에 push한다. 소식이 오면 내 세션이 `git fetch`해 변경을 보여 주고, 내가 보고 합친다. PR은 선택이다.

## 9. 소식과 기억

- 소식 다섯 가지: 팀원 끝남 · 중간 보고 · 질문 · 결재 필요 · 최종 답. 진행 줄은 보내지 않는다.
- 받는 길: 훅(`UserPromptSubmit`, 말을 걸 때마다 새 소식을 붙인다) + 상태 줄(늘 보임)이 기본. 채널(push)은 켤 수 있을 때. 기다리기(`agent_reply`)는 "끝날 때까지 기다려"일 때만.
- 자동 모으기: Claude Code 세션은 끝날 때 훅이 저장한다 (민감정보 지우기 그대로). 웹 대화는 확장이 저장한다.
- 기억 떠오르기: 말을 걸 때 훅이 관련 위키 몇 개를 함께 붙이고, 팀이 일을 시작할 때도 관련 기억을 싣는다.
- 어시스턴트의 기억: 에이전트마다 "일마다 새로" 또는 "앞 일의 메모 이어 받기". 메모는 AI가 끝나기 전에 `remember`로 남긴다.

## 10. 자라는 페이지

계속 쓸 결과물(여행지도 · 현황판 · 공부 노트)은 페이지로 둔다. 한 번 보는 파일은 결과물로 둔다.

- 방향(나만 고침, 고칠 때마다 AI에게 맨 먼저) · 데이터(`data.json`) · 화면(`index.html`) · 판(추가만, 보이는 판 고르기 · 되돌리기) · 바뀐 점(데이터 차이로).
- 입구: 콘솔 · 대화 · 내 세션 · 자동화 · 다른 어시스턴트. 같은 페이지의 고치기는 한 번에 하나(줄 서기), 다음 일은 새 판에서 출발한다.
- 비공개 페이지의 새 판은 바로 보이고, 공개 페이지의 새 판은 결재 뒤에 보인다.
- 고정 항목(내가 고친 것은 AI가 못 바꿈, 서버가 앞 판과 비교)은 2차.
- 내 세션은 최신 판을 내려받고, 내가 고친 것을 새 판으로 올릴 수 있다.

## 11. 자동화

레시피 하나 = 언제 · 누가 · 무엇을(지시 틀 + `{날짜}` · `{이벤트 내용}` · `{지난 결과}`) · 무엇으로 · 결과물 · 어디로 · 지킬 것. 스케줄을 넓힌다.

- 계기: 시간 · 손(지금 한 번) · 다른 자동화 끝남 · GitHub push · PR. 바깥 이벤트는 서명을 확인해 받고 내용은 믿지 않는 자료로 넘긴다.
- 결과물은 필수다. 안 나오면 그 회차는 실패. 방식은 "매번 새로"와 "정한 페이지 고치기" 둘. 매번 새로는 지난 회차 결과물을 재료로 붙인다.
- 기본 전달: 보관함 + 소식 + 폰 알림. 공개 · 전송은 결재 뒤.
- 지킬 것: 하루 한도 · 예산 · 앞 회차가 안 끝났으면 건너뜀 · 연속 실패면 멈추고 알림.

## 12. 블로그

블로그는 하나다. 모든 결과물은 블로그에 올릴지 · 공개할지가 정해지고, 안에서는 메뉴로 나눈다.

- 메뉴 종류: 글 목록 · 호 목록(매거진) · 페이지 모음 · 페이지 하나. 메뉴마다 이름 · 주소(`/<메뉴>`) · 편집 방침 · 운영 팀 · 읽을 지식 범위(위키 카테고리 + 담은 소재, `read_all`은 주지 않음) · RSS · 홈에 보이기.
- 공개는 두 단계: ① 올리기(메뉴에 자리, 나만 보며 실제 주소로 미리 보기) → ② 공개(내 스위치, 또는 AI 제안 → 결재). 초안에는 쓴 재료가 붙는다.
- 매거진: 호 = 표지 · 여는 글(페이지 · 글) + 기사(글) + 특집(자라는 페이지). 기획 → 원고 → 교정 → 발행 결재. 발행은 호 전체를 한 번에 결재한다.
- 주소는 `/<메뉴>/<이름>`. 옛 주소(`/posts/…` · `/pages/…`)는 넘겨준다. 예약된 이름(`admin` · `api` · `mcp` · `rss.xml` 등)은 메뉴 주소로 쓰지 못한다. 테마마다 도메인이 필요해지면 메뉴에 도메인 별칭을 붙인다.
- task(결과물)와 blog(게시물)는 이벤트로 잇는다 (지금 `task.page.built`와 같은 길). 모듈 사이 외래키는 없다.
- 메뉴는 보여 주는 분류이고 위키 카테고리(아는 것의 분류)와 따로다. 지금 쓰지 않는 `blog.categories`를 메뉴로 넓힌다.

## 13. 정리와 유지보수

- 정리는 서버 컴퓨터 안에서 한다: 규칙으로 되는 것은 일꾼(AI 없음), 판단이 필요한 것은 서버 러너의 정리 팀(제안 → 승인함).
- 세션 정리는 하루 한 번 모아서, 위키 · 보관함 점검은 매주. 더하기(연결선 · 카테고리 · 이름 붙이기)는 자동 적용, 합치기 · 지우기 · 공개 전환은 확인.
- maintainer는 스케줄로 점검(CLI 버전 · 의존성 · 실패 기록 · 스킬 시험 · 확장의 사이트별 읽기) → 보고서 → 고치고 검사 → PR → 결재 → 머지 → 배포 결재 → 서버 밖 배포 도구가 적용(실패하면 되돌림).

단계마다 시작할 때 인터페이스를 결재로 받고, 구현 · 검사 · 배포까지 한다.

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| 1 대화 · 맡기기 · 소식 | 대화의 참여자 · 목표 · 상태판, 소식함과 MCP 도구, 질문 사다리, 스킬 `cairn-team`, 훅(세션 자동 저장 · 소식 · 기억) · 상태 줄, 대화 중심 화면 | Claude Code에서 한 번 맡기면 팀 둘 이상이 동시에 일하고, 세션은 막히지 않으며 말을 걸 때마다 소식이 붙고, 질문에 세션이 답하고, 끝난 보고가 세션에 온다. 세션이 끝나면 저절로 저장된다 |
| 2 웹 | 브라우저 확장(모으기 · 보내기 · 맡기기 · 배지), Mac 러너의 AI 브라우저 조작, "내 Mac 리서치 팀" 템플릿 | ChatGPT 웹 대화가 세션으로 모이고, 페이지에서 맡긴 일이 HTML로 오고, AI 브라우저가 신청서를 채우고 제출 앞에서 결재를 올린다 |
| 3 AI끼리 품질 | 검토 짝, 받을 것 고르기와 검사, 한도 · 멈춤, 경쟁 두 안 | 검사에 떨어진 결과물을 팀이 고쳐 통과시키고, 점수 추이가 상태판에 남고, 한도에서 최선안으로 멈춘다 |
| 4 자라는 페이지 · 자동화 | 페이지의 방향 · 데이터 · 바뀐 점 · 줄 서기, 공개 판 결재, 자동화 레시피와 계기 | 여행지도가 매주 자동으로 새 판이 되고 바뀐 점이 소식으로 오며, 공개 판은 결재 뒤에 바뀐다 |
| 5 블로그 메뉴 · 매거진 | 메뉴 네 종류, 올리기 → 공개, 메뉴별 방침 · 팀 · 읽을 범위 · RSS, 매거진 호 | 매거진 호 하나가 기획부터 발행 결재 한 번까지 가고, 메뉴마다 RSS가 나온다 |
| 6 정리 · maintainer | 정리 범위 넓히기, 주간 점검, maintainer 순환 | 하루 한 번 세션이 정리되고, maintainer가 CLI · 스킬 · 확장을 고치는 PR을 올린다 |
